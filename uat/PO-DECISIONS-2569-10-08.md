# มติชั่วคราวระหว่างแก้ preship audit — 08/10/2569 (orchestrator ตัดสินแทน · **รอ PO ยืนยัน**)

> ผู้ใช้สั่งให้วนรอบ "แก้ → audit" ข้ามคืนโดยไม่รอ · ทุกข้อเลือกทางที่ปลอดภัย/เปิดเผยข้อมูลน้อยที่สุดที่ยังตรง spec · PO เปลี่ยนได้เมื่อรีวิว

| # | เรื่อง (issue) | ตัดสินชั่วคราว | เหตุผล |
|---|---|---|---|
| P1 | R3-009 ลง audit "login ถูกพัก" | ลง audit `LOGIN_RATE_LIMITED` **ครั้งแรกต่อ IP ต่อ 5 นาที** (ไม่รู้ IP = ต่อบัญชี/identifier — ปรับรอบ 5 R4-003 เพราะเปลี่ยน username ทุกคำขอแล้วลงได้ทุกครั้ง) — คำขอที่ถูกพักซ้ำในช่วงเดียวกันไม่ลงแถวใหม่ · login ผิดรหัส (`INVALID_CREDENTIALS`) / สำเร็จ / logout ยังลงทุกครั้งตาม `05` §13 | audit ลบไม่ได้และเก็บ 5 ปี — ผู้โจมตีไม่ต้อง login ยิงซ้ำเติมแถวได้ไม่จำกัด (ทดสอบ 35 วิได้ 868 แถว) · ยังเห็นสัญญาณการถูกพักครบทุกคู่บัญชี+IP · แนะนำเพิ่ม rate limit ที่ edge (Vercel Firewall) สำหรับ `/api/auth/login` |
| P2 | R3-001/008 ล็อกตรวจรหัส | คิวตรวจรหัสต่อ **บัญชี+IP** ในหน่วยความจำของ instance (แทนล็อก DB) + จำกัดตรวจพร้อมกัน **4 คำขอต่อ IP** (รอบ 5 R4-002 — สำนักงาน NAT เดียวกัน login พร้อมกันรอคิวสั้นๆ) | ล็อก DB ถือ connection ระหว่างเรียก Supabase ⇒ pool ตัน · ข้อจำกัด: หลาย instance พร้อมกันอาจเกินเพดาน 5 ครั้ง/บัญชี+IP ได้ไม่เกินจำนวน instance (เพดานรวมยังนับจาก audit ทุกครั้ง) |
| P3 | R3-003 แก้เคสพร้อมกัน | เพิ่ม error code `CASE_EDIT_CONFLICT` (409) ใน `38` §12 v3.12 — ฟอร์มที่เปิดก่อนคนอื่นบันทึก ถูกปฏิเสธทั้งคำขอ ให้เปิดเคสใหม่แล้วแก้อีกครั้ง (ไม่ merge อัตโนมัติ) | ทางที่ไม่ทำข้อมูลหายแน่นอน · ผู้เรียก API ที่ไม่ส่ง `expectedUpdatedAt` ทำงานแบบเดิม |
| P4 | R3-005 ข้อมูลเคสที่เพื่อนร่วมทีมเห็น (`41` §7.3) | เคสของเพื่อนร่วมทีมในแอปภาคสนามเห็น**เฉพาะ** เลขเคส · ชื่อลูกหนี้ · จังหวัด/อำเภอ · วันลงพื้นที่/ลำดับ · ชื่อพนักงาน · สถานะ — ไม่ส่งเลขบัตร/เบอร์/LINE/Facebook/ที่อยู่/ผู้ติดต่อ/เอกสาร/หลักฐาน/IMEI/มูลหนี้/ค่าคอม · รายการมุมมองทีมล้างยอดเงิน/ทรัพย์ของเคสเพื่อน · ใช้ allowlist (`lib/field/team-view.ts`) | PDPA — แถวสเปคระบุ "ชื่อลูกหนี้ + จังหวัด" (คำว่า "ข้อมูลเต็ม" บรรทัด 558 ตีความเป็นแค่ช่องเหล่านี้) · PO ต้องการเปิดเพิ่มให้แก้ allowlist จุดเดียว |
| P5 | R3-007 ยอดในพอร์ทัลเมื่อมีค่าธรรมเนียมโอนที่ตัดบัญชี (`97` · มติ U144) | ช่อง "ชำระแล้ว" ในพอร์ทัล = เงินรับ + ค่าธรรมเนียมโอนที่บริษัทรับภาระ ⇒ ยอดรวม = ชำระแล้ว + ภาษีที่ลูกค้าหัก + ค้างชำระ ลงตัว · ไม่เพิ่มคอลัมน์แยก | U144 ให้ "นับเป็นชำระแล้ว · ไม่แสดงแยกในพอร์ทัล" — จากมุมลูกค้าคือจ่ายครบ (ธนาคารหักค่าธรรมเนียมฝั่งเรา) |
| P6 | R3-004 ใบเสร็จไฟล์เดียวกันใช้ซ้ำ | ใช้ใบเสร็จ (SHA-256 เดียวกัน) ได้กับใบเบิก**ที่ยังไม่ถูกปฏิเสธ/แทนที่**ได้ใบเดียวทั้งองค์กร (ข้ามผู้เบิกด้วย) ไม่จำกัดเวลา ⇒ `CLAIM_DUPLICATE_SUBMISSION` (ขยายความหมายใน `24` v4.49) · ไม่ส่ง id ใบของคนอื่นกลับ | ใบเสร็จหนึ่งใบคือเอกสารจริงชิ้นเดียว — ป้องกันจ่ายซ้ำ · ยังไม่ครอบใบเสร็จที่ใช้เคลียร์เงินทดรอง (งานค้าง) |
| P7 | R3-013 ปุ่ม "ไม่รับเคส" | เพิ่มกล่องยืนยัน (danger) แสดงเลขเคส + เหตุผล + เตือนย้อนกลับไม่ได้ ก่อนส่ง | Rule 05 "Modal destructive ต้อง confirm" · mockup ยังไม่มีกล่องนี้ — **ยังไม่ได้แก้ mockup** (รอ PO ยืนยันรูปแบบ) |
| P8 | R3-017 ป้าย KPI รอบจ่าย | แท็บรอบจ่ายเปลี่ยนป้ายเป็น "ยอดโอนจริงที่รอจ่าย" (หักคืนเงินทดรองแล้ว) · ภาพรวมคง "เงินรอจ่าย (Payout)" = ยอดสุทธิ | สองนิยามถูกทั้งคู่แต่ชื่อเดียวกันทำให้สับสน |
| P9 | R3-038 ชื่อปุ่มปิดของ modal ดูอย่างเดียว | **ยังไม่เปลี่ยนชื่อ** — ปรับเฉพาะหน้าตาปุ่มยกเลิก/ปิดใน footer เป็นแบบมีกรอบ (secondary) ทั้งระบบ · ชื่อยังปนกัน "ปิด" / "ปิดหน้าต่าง" | mockup ใช้ "ปิดหน้าต่าง" (finance 17 · settings 13 · accounting 11 จุด) ขัดกับข้อแนะนำ audit ("ปิด") — **ต้องให้ PO เลือกชื่อเดียว** |
| P10 | R3-026 อัปโหลดไฟล์ | อัปโหลดแบบ signed URL ส่งด้วย anon key (ไม่แนบ JWT ผู้ใช้) เพื่อให้ยกเลิกคำขอได้จริง — token ของ server ใน URL คือสิทธิ์ | ทดสอบอัปโหลดจริงบน dev ผ่านแล้ว (ใบเสร็จค่าที่พัก PUT 200) · **ควรลองอัปโหลด 1 ครั้งบน staging หลัง push** |
| P11 | R7-009 วันตัดรอบที่ระบบเสนอตกงวดที่ปิด (ต่อจากมติ PO U146) | หน้าสร้างรอบวางบิล/รอบจ่าย: วันตามกติกาของรอบอยู่ในงวดที่ปิดแล้ว (`locked` / `sent_to_accountant`) ⇒ **เสนอวันนี้แทน** · เลือกวันในงวดปิดเอง ⇒ เตือนใต้ช่องทันที + ปุ่ม "ใช้วันนี้" · server ปฏิเสธด้วย `PERIOD_LOCKED_DIRECT_EDIT` (code เดิม) ข้อความให้เลือกวันใหม่ · endpoint อ่านอย่างเดียว `GET /api/finance/closed-periods` (`27` v3.20) | เอกสารใหม่ต้องลงงวดที่เปิดอยู่ · รอบใหม่ยังดึงรายการค้างของเดือนก่อนเข้าครบ (คัดทุกรายการที่ยังไม่เข้ารอบจนถึงวันตัดรอบ) แต่ป้ายงวดของรอบเป็นเดือนปัจจุบัน · ตัดสินชั่วคราว รอ PO ยืนยัน |
