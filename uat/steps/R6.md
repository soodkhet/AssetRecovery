### 0.3 State machine / ป้ายที่ใช้ (`23` §6.3/§6.5/§6.6/§6.8 · โค้ด `lib/compensation/approval.ts`)
**expense**: `pending_approval` (ขั้น 1) → อนุมัติขั้น 1 → `pending_finance_approval` (ขั้น ≥ 2 — **ขั้น 3 บริหารก็ใช้สถานะนี้**) → ขั้นสุดท้าย → `approved` · ตีกลับขั้นใดก็ได้ → `needs_revision` + `approval_step_current = 1` + ล้างตราผู้อนุมัติทุกขั้น → เจ้าของ "แก้ไขและส่งใหม่" → `pending_approval` (เริ่มขั้น 1 ใหม่)
- ป้าย stepper ✅: 'ขั้น 1/2: รอ ผู้จัดการทีมติดตามทรัพย์' · C5 fuel 'ขั้น 1/3' (projected จาก matrix แถว 2 ตั้งแต่ก่อนอนุมัติ) · '✓ ผ่านทุกขั้น' · '↩ ถูกตีกลับ — กลับไปขั้น 1' · ตัวกรอง 'ทั้งหมด | รอขั้น 1 (ผู้จัดการ) | รอขั้น 2 (การเงิน) | ถูกตีกลับ | อนุมัติแล้ว'
- `approval_step_total` / `approval_matrix_id` ใน DB = ค่า default (2 / NULL) จน**อนุมัติครั้งแรก** แล้ว snapshot จาก matrix (C5 fuel → 3, แถว 2 · อื่น ๆ → 2, แถว 1)
- ปุ่มต่อแถว (แท็บ 'ค่าตอบแทน' และตาราง 'รายการเบิก (Claims)' ในแท็บ 'รออนุมัติ'): **'อนุมัติขั้น N'** (ยิงทันที ไม่มี modal — toast 'อนุมัติแล้ว' '<ผู้รับ> — <ประเภท>') · 'ตีกลับ' → modal 'ตีกลับรายการเบิกให้แก้ไข' ปุ่ม 'ตีกลับรายการ' · 'ดูสูตร' · ปุ่มโผล่กับทุกแถวที่รออนุมัติถ้าผู้ใช้ถือ capability ขั้นใดก็ได้ (UX) — API ตรวจขั้นจริง

**revenue** (`19` §6.1 · `lib/warehouse/revenue-service.ts`): เกิดใน**ทรานแซกชันเดียวกับการอนุมัติขั้นสุดท้าย**ของ expense ที่ทำให้ "expense active ทุกใบของเคส (ไม่นับ superseded/rejected) = approved" และ asset ของเคสอยู่ในล็อต `confirmed` · `revenue_date` = วันที่ `cases.closed_at` เวลาไทย (ไม่ใช่วันที่อนุมัติ) · VAT จาก `vat_rate_history` (7.00 ตั้งแต่ 2025-10-01) → `vat_rate_pct_used` · `vat_mode_snapshot` จากบริษัท (Q6) · `created_by` = ผู้กดอนุมัติใบสุดท้าย · **ไม่มีแถว audit ของ `revenues` เอง** — ดูได้จาก `after.revenue_ids_created` ใน audit `approve` ของ expense ใบนั้น
**advance**: `pending_approval` → `approved` (การเงิน) | `rejected` (เหตุผล ≥ 5) · `approved|overdue` → เคลียร์ → `cleared` · `approved` → job → `overdue` · ห้ามมี `approved|overdue` 2 ใบต่อ payee (partial unique `uniq_active_advance_per_payee` → `ADVANCE_PENDING_SETTLEMENT`)
**payout_batch**: สร้าง → `draft` (transient) → `checking` → สร้างไฟล์ → `file_generated` (สร้างซ้ำได้ — เตือน) → ยืนยันจ่าย → `completed`
**billing_batch**: สร้าง → `draft` → 'ส่งบิล' → `sent` (→ `partially_paid`/`paid` ใน R7) · 1 บริษัท 1 งวด = 1 รอบ (`UNIQUE(org, company, period)`)
