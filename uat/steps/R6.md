### 0.3 State machine / ป้ายที่ใช้ (`23` §6.3/§6.5/§6.6/§6.8 · `lib/compensation/approval.ts`, `approval-ui.ts`)
**expense**: `pending_approval` (ขั้น 1) → อนุมัติขั้น 1 → `pending_finance_approval` (ขั้น ≥ 2 — **ขั้น 3 บริหารก็ใช้สถานะนี้**) → ขั้นสุดท้าย → `approved` · ตีกลับขั้นใดก็ได้ → `needs_revision` + `approval_step_current = 1` + ล้างตราผู้อนุมัติทุกขั้น → เจ้าของ 'แก้ไขและส่งใหม่' → `pending_approval` (เริ่มขั้น 1 ใหม่ · SoD นับเฉพาะรอบหลังตีกลับ)
- ป้าย 📄: `ขั้น {cur}/{total}: {role}` เช่น 'ขั้น 1/2: ผู้จัดการทีมติดตามทรัพย์' · C5 fuel 'ขั้น 1/3' (projected matrix แถว 2) · '✓ ผ่านทุกขั้น' · '↩ ถูกตีกลับ — กลับไปขั้น 1' · ตัวกรอง 'ทั้งหมด | รอขั้น 1 (ผู้จัดการ) | รอขั้น 2 (การเงิน) | ถูกตีกลับ | อนุมัติแล้ว'
- ปุ่มรายแถว 📄 (แท็บ 'ค่าตอบแทน' + ตาราง 'รายการเบิก (Claims) — อนุมัติหลายขั้น' ในแท็บ 'รออนุมัติ'): **'อนุมัติขั้น {n}'** (ยิงทันที ไม่มี modal — toast 'อนุมัติแล้ว' '<ผู้รับ> — <ประเภท>') · **'ตีกลับ'** → modal 'ตีกลับรายการเบิกให้แก้ไข' ปุ่ม 'ตีกลับรายการ' → toast 'ตีกลับให้แก้ไขแล้ว' 'รายการกลับไปเริ่มที่ขั้น 1 ใหม่ทั้งหมด' · ปุ่มโผล่**เฉพาะแถวที่รอขั้นของผู้ใช้** (`viewerCanAct`)
- **การมองเห็นคิว** (`isApprovalItemVisibleTo`): แถวที่รออนุมัติ เห็นเมื่อถือ capability ของขั้นใดขั้นหนึ่งตั้งแต่ 1 ถึงขั้นที่ค้าง ⇒ ผู้จัดการเห็นแถวทีมตัวเองทุกขั้น · การเงินเห็นตั้งแต่ขั้น 2 · บริหารเห็นเฉพาะขั้น 3 · แถว `approved`/`needs_revision` ทุกผู้อนุมัติใน scope เห็น · Superadmin เห็นหมด
- scope ทีม (`scopeFilter`): ผูกงาน = ทีมของงาน · ไม่ผูกงาน = ทีมของผู้เบิก (payee → user → team) · การเงิน/บริหาร = ทั้งองค์กร
- `approval_step_total`/`approval_matrix_id` snapshot ตอน**อนุมัติครั้งแรก** (C5 fuel → 3 แถว 2 · อื่น ๆ → 2 แถว 1) · hotel snapshot แล้วตั้งแต่ R4.38b (2 / แถว 1)

**revenue** (`19` §6.1 · `lib/warehouse/revenue-service.ts`): เกิดใน**ทรานแซกชันเดียวกับการอนุมัติขั้นสุดท้าย** ของ expense ที่ทำให้ expense active ทุกใบของเคส (ไม่นับ superseded/rejected — **รวมแถวรายวัน**) = approved + asset อยู่ในล็อต `confirmed` + วันลงพื้นที่ settle แล้ว (`field_days_not_settled` ผ่านตั้งแต่ R4.23b) · ล็อกแถว `cases` ก่อนประเมิน (BUG-089) · `revenue_date` = วันที่ `cases.closed_at` เวลาไทย = **2026-10-04** · VAT 7.00 จาก `vat_rate_history` → `vat_rate_pct_used` · `vat_mode_snapshot` (Q6) · `created_by` = ผู้กดอนุมัติใบสุดท้าย · ไม่มีแถว audit ของ `revenues` เอง — ดู `after.revenue_ids_created` ใน audit `approve` ของ expense ใบนั้น
**case_evidences C3** (Q14 + `a26f7cf`): `pending → approved` ตอน expense active **ใบสุดท้าย**ของ C3 approved (ไม่ใช่ใบแรก) — audit `after.evidence_approved_id` ของใบนั้น
**advance**: `pending_approval` → `approved` (การเงิน) | `rejected` (เหตุผล ≥ 5) · `approved|overdue` → เคลียร์ → `cleared` · ห้าม `approved|overdue` 2 ใบต่อ payee (`uniq_active_advance_per_payee` → `ADVANCE_PENDING_SETTLEMENT`) · ใช้เกิน → คืน 0 + สร้าง expense `manual` ส่วนเกินอัตโนมัติ (Q3)
**payout_batch**: สร้าง → `checking` → สร้างไฟล์ → `file_generated` (สร้างซ้ำได้ — เตือน) → ยืนยันจ่าย → `completed` (+ `expense_records` ทุกรายการ + `wht_certificates` ต่อรายการที่ WHT > 0)
**billing_batch**: สร้าง → `draft` → 'ส่งบิล' → `sent` (→ `paid` ใน R7) · 1 บริษัท 1 งวด = 1 รอบ

### คำถามเชิงบัญชี — orchestrator ตัดสินตามมาตรฐานไทยไปก่อน (golden ยึดโค้ดปัจจุบัน · จดให้นักบัญชีรีวิว)
- **A1 ค่าที่พัก/คำขอเบิกส่วนเกินอยู่ในฐาน WHT** (โค้ดนับรวม ⇒ in1 ฐาน 195000 หัก 1800 จาก hotel) · **เสนอ**: ค่าใช้จ่ายที่จ่ายคืนตามจริง (reimbursement) **ใบเสร็จออกในนามบริษัท** = ค่าใช้จ่ายของบริษัทเอง ไม่ใช่เงินได้ของผู้รับ ⇒ **ไม่รวมฐาน/ไม่หัก** · ถ้าใบเสร็จออกในนามบุคคล = ถือเป็นส่วนหนึ่งของค่าตอบแทน ⇒ รวมฐาน (แนวปฏิบัติกรมสรรพากรเรื่องค่าใช้จ่ายที่ผู้รับจ้างเรียกเก็บเพิ่ม) · ค่าน้ำมัน/เบี้ยเลี้ยง**เหมาจ่าย** = เงินได้ ⇒ รวมฐาน (ถูกแล้ว) · ถ้ายึดข้อเสนอ: in1 ฐาน 135000 → WHT 4050 · IN-1 net 490950 · 50 ทวิ in1 6 ใบ ⇒ ต้องเพิ่มฟิลด์ "ใบเสร็จในนามบริษัท" ทีหลัง · **UAT คงโค้ด** (ไม่บล็อก)
- **A2 50 ทวิ ต่อรายการ (15 ใบ) vs ต่อ payee ต่อการจ่าย** · **เสนอ 1 ใบต่อ payee ต่อรอบจ่าย** (ม.50 ทวิ ให้ออกหนังสือรับรองทุกครั้งที่หักภาษี — การจ่ายครั้งเดียวที่รวมหลายรายการออกใบเดียว แยกบรรทัดตามประเภทเงินได้) ⇒ 3 ใบ (in1, in2, out1) ยอดรวม 28500 เท่าเดิม · ภ.ง.ด.3 ยื่นเป็นรายผู้รับ ต่อการจ่าย · UAT คง 15 ใบ
- **A3 ประเภทเงินได้บน 50 ทวิ/ภ.ง.ด.3** — ค่าตอบแทนพนักงานติดตามที่เป็นบุคคลธรรมดาไม่ใช่ลูกจ้าง: ถ้าเป็นการ "รับทำงานให้" = **40(2)** ซึ่งตามกฎหมายหักตาม ม.50(1) (อัตราก้าวหน้า) ไม่ใช่ 3% คงที่ · อัตรา 3% + เกณฑ์ ฿1,000 (ท.ป.4/2528 ข้อ 12) ใช้กับค่าจ้างทำของ/ค่าบริการ **40(8)** · **เสนอ**: ให้นักบัญชียืนยันการจัดประเภท (ส่วนใหญ่ธุรกิจลักษณะนี้จัดเป็นค่าบริการ 40(8) + สัญญาจ้างทำของ ⇒ 3% ใช้ได้) · ไม่กระทบ UAT
- **A4 เกณฑ์ ฿1,000 ต่อ payee ต่อรอบจ่าย (Q5)** — สอดคล้อง ท.ป.4/2528 "จ่ายครั้งหนึ่งต่ำกว่า 1,000 บาทไม่ต้องหัก" (การจ่าย = การโอนครั้งเดียวของรอบ) · ข้อยกเว้น: สัญญาเดียวที่ตกลงยอดรวม ≥ 1,000 แต่ทยอยจ่ายต้องหักทุกงวด — ไม่เกิดใน UAT · **เสนอ ยอมรับ**
