## ⚠️ อ่านก่อน: flow C7 ถูกปรับจาก UAT_PLAN ให้ตรง spec (เหตุผล)

UAT_PLAN §5/DATASET เขียนว่า "C7 → มอบหมายแล้ว**ไม่มีใครรับ** → `reassign_timeout` → มอบหมายใหม่" — **ทำแบบนั้นแล้ว job จะไม่ทำอะไรเลย** เพราะตาม `docs/40` §8–§11 + โค้ด:

| สถานการณ์ | spec/โค้ดทำอะไร |
|---|---|
| มอบหมายแล้ว พนักงาน**ยังไม่กดรับ** (`pending_accept` = "assigned") | ไม่มี timeout ใด ๆ · `accept_deadline_hours` บันทึกได้แต่**ยังไม่บังคับ** (`40` §11) · ผู้จัดการ "เปลี่ยนผู้รับผิดชอบ" ได้**ทันที**ไม่ต้องรอใคร (resolution = `consented` โดยปริยาย) |
| พนักงาน**กดรับแล้ว** (`accepted_unscheduled`) แล้วผู้จัดการขอเปลี่ยนคน | สร้าง `pending_reassignments` สถานะ `waiting_consent` + `expires_at = requested_at + reassign_timeout_hours` → คนเดิม ยินยอม / ไม่ยินยอม(เหตุผล) / **ไม่ตอบจนเลย `expires_at` → job `reassign_timeout` โอนให้คนใหม่อัตโนมัติ (`timeout_auto`)** |

`lib/assignments/timeout-job.ts` เลือกเฉพาะ `status='waiting_consent' AND expires_at <= now` ⇒ **timeout ใช้กับ "คำขอเปลี่ยนผู้รับผิดชอบที่รอความยินยอม" เท่านั้น** ไม่ใช่ "มอบหมายแล้วไม่กดรับ"

**flow C7 ที่ใช้ใน R3** (คงเจตนา "in2 ไม่ตอบสนอง → ระบบโอนให้ in1"):
`sup.in` มอบหมาย C7 → in2 → **in2 กดรับงาน C7 (ข้อยกเว้นเดียวที่กดรับใน R3)** → admin ตั้ง timeout = 1 ชม. (**ต้องตั้งก่อนส่งคำขอ** — `expires_at` ถูก snapshot ตอนสร้างคำขอ ค่าใหม่ไม่คำนวณย้อน `40` §6.4) → `mgr.in` ขอเปลี่ยน C7 → in1 (เหตุผล) → in2 **ไม่ตอบ** → สั่ง job ก่อนหมดเวลา (ต้องไม่ทำอะไร) → รอเลย `expires_at` → สั่ง job → C7 เป็นของ in1 สถานะ `pending_accept` (in1 กดรับใน R4)

**วิธีทำให้หมดเวลา** — ค่าต่ำสุด 1 ชม. (มติ PO: 1–168) · job ใช้นาฬิกาเครื่อง (`runJobById(id, new Date())`) — **ไม่มีช่องส่ง `now` ปลอมผ่าน `/api/dev/trigger-job`** ⇒ 2 ทาง:
- **ทาง A (แนะนำ — ไม่แตะ DB):** ส่งคำขอ C7 ให้เร็วที่สุดในรอบ (R3.10) แล้วเดิน step อื่นต่อ (R3.11–R3.19) จากนั้น R3.20 **รอจริง**จนเลย `expires_at` (poll ด้วย SQL ทุก 1–2 นาที — ปกติเหลือรอ 20–40 นาที)
- **ทาง B (fixture time-travel — orchestrator ตัดสินเท่านั้น, role agent ห้ามทำเอง):** ถ้าเวลาไม่พอ ใช้ psql ที่เขียนได้ (ไม่ใช่ `q.sh`):
  ```sql

   WHERE case_id = 'f476e94f-3375-425f-b6a7-0895e93f33a6' AND status = 'waiting_consent';
  ```

  ถ้าใช้ทาง B ต้องจดในรายงานว่า `expires_at` ถูกแก้ด้วย fixture (ค่าเดิม = requested_at + 1 ชม. ตรวจไว้แล้วใน R3.10)

## 0. ก่อนเริ่ม

### 0.1 State machine (`docs/40` §9–§10 · enum `assignment_status` ใน `02` §3 — **`23` ไม่มี state ของ assignment**)
```
case.status = approved (ไฟล์ 38) ─ ไม่มีแถว active ─► ready_to_assign "พร้อมมอบหมาย"
  ─assign (POST /api/cases/:id/assign {agentId})──────────────► pending_accept   = "มอบหมายแล้ว (รอรับ)"
  pending_accept ─accept (พนักงาน: POST /api/field/cases/:id/accept)► accepted_unscheduled = "รับงานแล้ว"
  pending_accept ─reassign (reason ≥5)──► แถวเดิม reassigned_away + แถวใหม่ pending_accept (ทันที)
  accepted_*     ─reassign (reason ≥5)──► pending_reassignments.waiting_consent (เคสยังเป็นของคนเดิม)
        ├─ consent  → แถวเดิม reassigned_away + แถวใหม่ pending_accept (accepted_at=NULL)
        ├─ decline (decline_reason) → ไม่มีอะไรเปลี่ยน
        └─ job reassign_timeout หลัง expires_at → เหมือน consent แต่ resolution = timeout_auto
```
- active = `pending_accept, accepted_unscheduled, scheduled, needs_revision` (1 เคส : 1 แถว active ต่อ tracking_round — `40` §11)
- **การกดรับงานเป็นของพนักงานภาคสนาม** (`40` §13 `accept_assignment` = Field Agent) ⇒ ทุกเคส**ยกเว้น C7-รอบแรก**ปล่อยค้าง `pending_accept` ให้ R4 กดรับ
- Error code ของโมดูลนี้นิยามใน **`40` §12** (ไม่ใช่ `24` ซึ่งเป็น finance validation): `ASSIGNMENT_TEAM_MISMATCH`(400) `ASSIGNMENT_ALREADY_EXISTS`(400) `ASSIGNMENT_REASON_REQUIRED`(400) `ASSIGNMENT_NOT_FOUND`(404) `ASSIGNMENT_INVALID_STATUS`(400) `REASSIGNMENT_ALREADY_PENDING`(400) `REASSIGNMENT_ALREADY_TIMED_OUT`(400) `DECLINE_REASON_REQUIRED`(400) `CASE_NOT_FOUND`(404) `TEAM_NOT_FOUND`(404) + `PERMISSION_DENIED`(403, `24` §6.9) · Zod ไม่ผ่าน = 400 `REQUIRED_MISSING`

## E. หมดเวลา → job → ตรวจผล

### R3.20 รอจนเลย `expires_at` แล้วสั่ง job (ทาง A) — C7 โอนให้ in1 อัตโนมัติ
- ทำ: poll `uat/bin/q.sh "select now() > expires_at as expired, expires_at - now() as remain from pending_reassignments where status='waiting_consent'"` ทุก 1–2 นาทีจน `expired = t` (ระหว่างรอ: หน้า mgr.in badge C7 ต้องขึ้น "หมดเวลาแล้ว — รอระบบเปลี่ยนให้อัตโนมัติ" เมื่อเลยเวลาแต่ยังไม่รัน job → ภาพ `R3.20-expired-badge`) · ถ้าเวลาไม่พอ → **หยุดถาม orchestrator เรื่องทาง B ห้ามแก้ DB เอง**
- ทำ: admin `POST /api/dev/trigger-job {jobType:'reassign_timeout'}`
- คาดหวัง API: 200 `duplicate:false` · job `completed` · result `{due:1,resolved:1,skipped:0,caseIds:['<C7>']}`
- หลังบ้าน:
  - `pending_reassignments` → `timeout_auto`, `resolved_at` ไม่ว่าง, `resolved_by` NULL
  - `case_assignments` C7: แถว in2 → `reassigned_away` (accepted_at คงค่าเดิม) + แถวใหม่ **in1 `pending_accept`, `accepted_at` NULL, `reassigned_from` = แถว in2, `reassign_reason` = เหตุผล R3.10**
  - `reassignment_history` 1 แถว resolution `timeout_auto`, `was_accepted_before_reassign` t, from in2 → to in1 (จด `reassigned_by` — โค้ดใส่ผู้สร้างแถวเดิม (sup.in) ไม่ใช่ผู้ขอ mgr.in → 🐞-R3-F)
  - audit `update` `case_assignments` actor_id NULL (ระบบ) reason ขึ้นต้น `[job:<jobId>] หมดเวลารอความยินยอม — …` events `assignment.reassignment_timeout_resolved`
  - noti `assignment.reassignment_timeout_resolved` "คำขอเปลี่ยนผู้รับผิดชอบหมดเวลารอคำตอบ" ถึง **in2, in1, mgr.in** คนละ 1 แถว (link `/cases/assign`)
- คาดหวังบนจอ (mgr.in reload): C7 "มอบหมายแล้ว (รอรับ)" อนันต์ + `มอบหมายเมื่อ <เวลารัน job>` · badge คำขอหาย · ปุ่ม `เปลี่ยนผู้รับผิดชอบ` กลับมา

### R3.21 **probe** job รันซ้ำต้องไม่สร้างซ้ำ (idempotent)
- ทำ: ยิง trigger อีกครั้ง**นาทีเดียวกับ R3.20** → แล้วรอขึ้นนาทีใหม่ยิงอีกครั้ง
- คาดหวัง: นาทีเดียวกัน → `duplicate:true` job id เดิม · นาทีใหม่ → job ใหม่ `completed` result `{due:0,resolved:0,…}` · **ไม่มี**แถวเพิ่มใน `case_assignments` / `reassignment_history` / notifications `assignment.reassignment_timeout_resolved` (ยังคง 3 แถว) / audit `update` C7

### R3.22 in2 ตอบช้า + ตรวจหน้า field (ห้ามกดรับ)
- ทำ: `uat.agent.in2` API `POST /api/cases/<C7>/reassignment/respond {decision:'consent'}` และ `{decision:'decline',declineReason:'probe ตอบหลังหมดเวลา'}`
- คาดหวัง: ทั้งคู่ 400 `REASSIGNMENT_ALREADY_TIMED_OUT` · ไม่มีอะไรเปลี่ยน
- ทำ: มือถือ `/field/pending` ของ in1, in2, out1 (**อ่านอย่างเดียว ห้ามกด `รับงาน`**)
- คาดหวัง: in1 รอรับงาน **3** (C1, C2, C7) · in2 รอรับงาน **2** (C3, C4) และไม่มี C7 ในทุกแท็บ (อาจมีข้อความ `เคส "นางสาวปิยะ เงียบ" ถูกโอนไปแล้วเพราะไม่ได้ตอบทันเวลา`) ไม่มี popup คำขอค้าง · out1 รอรับงาน **1** (C5) · ทุกการ์ดมี "มอบหมายเมื่อ DD/MM/25xx HH:mm" · ภาพ `R3.22-<user>-pending`
