### 0.3 State machine ที่ใช้
**asset** (`44` §9.1 · โค้ด `lib/warehouse/asset-status.ts`):
```
pending_intake ─รับเข้าคลัง─► in_custody ─ใส่ล็อต─► handover_pending ─ล็อต confirmed─► handed_over (terminal)
pending_intake ─ตีกลับ (reason บังคับ)─► intake_rejected ─'รับใหม่' (modal เดิม)─► in_custody   (โค้ดข้ามตรง ๆ ไม่ผ่าน pending_intake — ผลเท่ากัน · event asset.intake_retry)
```
**handover_lot** (`44` §9.2): สร้าง `finance_pickup` → `pending_attach` (แท็บ 'รอส่งมอบ') · สร้าง `we_deliver` → `pending_delivery_proof` (แท็บ **'ส่งมอบแล้ว'** ทันที) · แนบครบ + ยืนยัน → `confirmed` (terminal)
**expense**: ยืนยันล็อต → แถว `pending_warehouse_confirm` ของเคสในล็อต → `pending_approval` (superseded ไม่แตะ) · C3 ไม่ผ่านคลัง (ค้าง `pending_approval` จาก R4)
**case_evidences** (Q14): รับเข้าคลังสำเร็จ → แถวล่าสุดของเคส (outcome `closed_success`, status `pending`) → `approved` (reviewed_by = ธุรการ) · แถว `rejected` เดิมของ C4 ไม่แตะ · C3 ค้าง `pending` (ผ่านใน R6 เมื่อค่าตอบแทนอนุมัติครบ) · ตีกลับ intake **ไม่**ทำให้หลักฐานผ่าน

### 0.4 Error code ที่คาด (`lib/warehouse/errors.ts` · 400 เว้นระบุ)
`INTAKE_MISSING_CONDITION` 'ยังไม่ได้เลือกสภาพเครื่อง' · `INTAKE_MISSING_NOTE` 'ต้องระบุรายละเอียดสภาพเครื่อง' · `REJECT_MISSING_REASON` 'ต้องระบุเหตุผลที่ตีกลับ' · `MIXED_COMPANY_LOT` 'ล็อตเดียวมีได้บริษัทเดียว' · `EMPTY_LOT` 'ยังไม่ได้เลือกเครื่อง' · `ASSET_NOT_IN_CUSTODY` 'มีเครื่องที่ยังไม่อยู่ในคลัง' · `ASSET_ALREADY_IN_LOT` 'มีเครื่องที่อยู่ในล็อตอื่นแล้ว' (context.lotNumbers) · `LOT_MISSING_SIGNED_DOC` · `LOT_MISSING_DELIVERY_PROOF` · `LOT_ALREADY_CONFIRMED` 'ล็อตนี้ยืนยันส่งมอบแล้ว' · `ASSET_INVALID_STATUS` · **404** `ASSET_NOT_FOUND` 'ไม่พบเครื่อง' / `LOT_NOT_FOUND` 'ไม่พบล็อตส่งมอบ' (ข้อความเดียวกันทั้ง "ไม่มีจริง" และ "นอก scope") · `CONFIRM_TRANSACTION_FAILED` (500 — **ต้องไม่เกิด**)
- อัปโหลด: `UPLOAD_PATH_OUT_OF_SCOPE` 'ที่อยู่ไฟล์ไม่ถูกต้อง' · `UPLOAD_FILE_NOT_FOUND` 'ไม่พบไฟล์ที่แนบ' · `UPLOAD_FILE_TYPE_INVALID` 'ชนิดไฟล์ไม่รองรับ' · `UPLOAD_HASH_MISMATCH` 'ไฟล์ไม่ตรงกับที่อัปโหลด'
- Zod = `REQUIRED_MISSING` + `fields` (IMEI 14 หลัก/มีขีด, we_deliver ไม่มีที่อยู่, ปี พ.ศ. ใน scheduledAt, assetIds ซ้ำ) · `PERMISSION_DENIED` (403) · `EVIDENCE_REJECT_AFTER_FINAL` (400 — `lib/field/errors.ts`)
- **`IMEI_MISMATCH` ไม่ใช่ error** — มากับ `warning` ของ envelope (200) · ข้อความ ✅ 'IMEI ที่ตรวจจริงไม่ตรงกับสัญญา' / 'ระบบบันทึกค่าที่ตรวจจริงไว้แล้วและรับเข้าคลังต่อได้ — แนะนำให้ตีกลับถ้าไม่มั่นใจ'
