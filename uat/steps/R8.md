### 0.4 State machine / สิทธิ์ 📄
- **accounting_period** (`lib/accounting/period.ts` `PERIOD_TRANSITIONS` · `23` §6.13): `collecting → sent_to_accountant` (send — ผ่าน Readiness) · `sent_to_accountant → locked` (lock) · `locked → sent_to_accountant` (unlock — **ไม่กลับ collecting**) · ยาม action: send ต้อง `collecting`, lock ต้อง `sent_to_accountant`, unlock ต้อง `locked` ไม่งั้น `PERIOD_INVALID_STATUS` · lock **ไม่ตรวจ Readiness/critical ซ้ำ** (ตาม `30` — readiness เป็นเงื่อนไขของ send)
- ป้าย (`PERIOD_LOCK_POLICY`): 'กำลังรวบรวม' / 'ส่งสำนักงานบัญชีแล้ว' ('จำกัด — เฉพาะฟิลด์ที่ไม่กระทบยอดที่ส่งไปแล้ว') / 'ปิดรอบแล้ว' ('แก้ไขโดยตรงไม่ได้' · 'บังคับใช้ Adjustment 100%')
- ยามกลาง `assertPeriodEditable` (`lib/settings/period-lock.ts`): `locked` = ปัดทุกการเขียน · `sent_to_accountant` = ปัดเฉพาะ `affectsAmount=true` (ค่าเริ่มต้น) · ไม่มีงวด = ผ่าน · ⚠️ **งวดที่ "ส่งแล้ว" ก็ได้ code `PERIOD_LOCKED_DIRECT_EDIT` ข้อความเดียวกัน** 'รอบบัญชีถูกล็อกแล้ว'
- วันที่ที่ยามใช้หางวด (📄): เงินทดรอง = **วันนี้** (create/approve/reject/settle) · manual claim/hotel = `expenseDate` · รอบจ่ายใหม่ = `cutoffDate` · รอบจ่ายเดิม = `created_at` · รอบวางบิล = ป้าย `period` · ใบกำกับ = `invoice_date` · 50 ทวิ = `payment_date` · statement = วันที่แถว · cost center = `expense_records.period_id`
- **adjustment** (`lib/adjustments/adjustment.ts` · `23` §6.9): `pending_approval → approved | rejected` (terminal ทั้งคู่) · `period_status_at_target` snapshot ตอนสร้าง (จากวันที่ของเป้าหมาย) → ระดับอนุมัติ (`lib/finance/adjustment-approval-policy.ts`): collecting = การเงิน · sent_to_accountant = **การเงิน + บริหาร** (อนุมัติบางส่วนสถานะยังรอ) · locked = **บริหารเท่านั้น** (capability `approve_adjustment_locked`) + audit แยก (`action='unlock'` บน adjustments)
- ยอด Adjustment บวกเสมอ ทิศทางที่ `adjustment_type` · รายงานใช้ `netAfterAdjustments()` นับเฉพาะ `approved` · **รายได้: ปรับที่ฐานก่อน VAT (`revenues.gross_satang`)** ในรายงานกำไร/สรุปรายได้/scorecard (แต่ฟอร์มแสดง "ยอดปัจจุบัน" = `total_satang` รวม VAT — ดู ❓-R8-1)
- **exception**: `open → resolved | authorized` · authorize = ผู้บริหาร (`authorize_exception`) + เหตุผลบังคับ (`AUTHORIZED_EXCEPTION_REASON_REQUIRED`) · สร้าง/อนุมัติยกเว้นได้แม้งวด locked (ไม่มียามงวด) · Export Pack ปัดเมื่อมี critical `open` เท่านั้น (authorized ผ่าน)
- สิทธิ์จริงในฐาน (q.sh 04/10/2569): `manage_accounting_period` = บัญชี · `unlock_period` = บริหาร · `create_adjustment` = การเงิน · `approve_adjustment` = การเงิน+บริหาร · `approve_adjustment_locked` = บริหาร · `authorize_exception` = บริหาร · `manage_exceptions` = บัญชี (การเงิน view) · `export_accounting_pack` = บัญชี (การเงิน view) · `map_cost_center` = บัญชี (การเงิน view) — ตรง `25` §7.4
- route: lock/unlock เปิดให้ `manage_accounting_period` **หรือ** `unlock_period` (ล็อกได้ทั้งบัญชีและผู้บริหาร) · unlock ชั้นสองโยน `UNLOCK_REQUIRES_EXECUTIVE` (403) ให้บัญชี · GET `/api/accounting/periods` = `manage_accounting_period|unlock_period` เท่านั้น ⇒ **การเงินได้ 403** (ขัด `30` §12 "ดูภาพรวม: การเงิน" — R8.03)

## 📒 คำถามเชิงบัญชี (เสนอคำตอบตามมาตรฐานไทย — รอนักบัญชี/ผู้ใช้ยืนยัน)
- **B1 ลดค่าบริการหลังออกใบกำกับและรับเงินแล้ว** → ต้องออก**ใบลดหนี้** (ป.รัษฎากร ม.86/10) ยอด 100.00 + VAT 7.00 = 107.00 และลดภาษีขายใน**เดือนที่ออกใบลดหนี้** (ไม่ย้อนแก้ ภ.พ.30 ของ ต.ค.) · คืนเงินหรือหักกลบบิลถัดไปของ CO1 · ระบบไม่มีใบลดหนี้ ⇒ สำนักงานบัญชีออกนอกระบบตาม 07_Adjustment_Log (R8-N10)
- **B2 Adjustment ของงวดที่ปิดแล้วลงงวดไหน** → รายงานบริหารแสดงยอดสุทธิในงวดเดิม (ตามโค้ด `20` §9) · ในสมุดบัญชี (สำนักงานบัญชี) ถ้ายอดไม่มีสาระสำคัญ บันทึกในงวดปัจจุบันที่ยังเปิด (TAS 8 — ไม่ใช่การแก้ไขข้อผิดพลาดย้อนหลัง) ⇒ ข้อเสนอ: export ถัดไปแสดง Adjustment ที่อนุมัติหลังล็อกแยกหัวข้อ "ปรับปรุงงวดก่อน"
- **B3 ค่าธรรมเนียมโอนของธนาคาร** → เป็นค่าใช้จ่ายของบริษัท (ค่าธรรมเนียมธนาคาร) ไม่ใช่เงินได้ของผู้รับ ไม่อยู่ในฐาน WHT ⇒ ปฏิเสธ A2 ถูกต้อง
- **B4 ภาษีที่ลูกค้าหัก 111.90 แต่ยังไม่ได้ 50 ทวิ** → นำไปเครดิตใน ภ.ง.ด.50/51 ไม่ได้จนกว่าจะมีหนังสือรับรอง · การอนุมัติยกเว้นเพื่อปิดงวดได้ แต่ต้องติดตามเอกสาร (ต่อจากมติ A8)
- **B5 ปลดล็อกงวด** → ทำได้เฉพาะผู้บริหารพร้อมเหตุผลและ audit แยก · หลังปลดล็อกให้แก้ผ่าน Adjustment เท่านั้นแล้วล็อกใหม่ (`30` §9) — สอดคล้องการควบคุมภายในที่ดี
