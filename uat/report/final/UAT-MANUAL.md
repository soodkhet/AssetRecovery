## 1. ภาพรวมการไหลของงาน

```
ธุรการรับเคส → ผู้ตรวจเคสรับ + ยืนยันทีม → ผู้จัดการ/หัวหน้าทีมมอบหมาย → พนักงานรับงาน/นัดวัน/เช็คอิน/ปิดงาน
   → (สำเร็จ) คลังรับเครื่อง → สร้างล็อต (1 ล็อต = 1 บริษัท) → ยืนยันส่งมอบ
   → อนุมัติค่าตอบแทน (ผู้จัดการ → การเงิน → บริหารถ้าเกินเพดาน) → รายได้เกิดอัตโนมัติ
   → การเงิน: รอบจ่าย/ไฟล์โอน/50 ทวิ/วางบิล → บัญชี: กระทบยอด/ใบกำกับ/ภ.ง.ด./Export Pack/ส่งสำนักงานบัญชี
   → บริหาร: ล็อกงวด / Adjustment / รายงาน
```

**รายได้เกิดเมื่อ** รายการเบิกของเคสได้รับอนุมัติครบทุกใบ **และ** ล็อตส่งมอบยืนยันแล้ว — เกิดครั้งเดียวต่อเคส · เคสปิดไม่สำเร็จไม่ผ่านคลัง

## 2. ผู้ดูแลระบบ (Superadmin)

เมนู "การตั้งค่า" เปิดที่หน้า "สิทธิ์การใช้งาน" · แถบย่อย: สิทธิ์การใช้งาน · ผู้ใช้งาน · แผนค่าตอบแทน · เทมเพลตค่าบริการ · ทีมติดตามทรัพย์ · บริษัทไฟแนนซ์ · ตั้งค่าบัญชี/การเงิน · Audit Log · Job Log

![](../../shots/R1/R1.01-settings-home.png)

ลำดับตั้งค่าที่แนะนำ: เทมเพลตค่าบริการ → บริษัทไฟแนนซ์ → แผนค่าตอบแทน → ทีม → ผู้ใช้งาน → Payee/สายอนุมัติ/นโยบาย → นโยบายมอบหมายงาน

### 2.1 เทมเพลตค่าบริการ
1. การตั้งค่า → เทมเพลตค่าบริการ → **+ สร้างเทมเพลต**
2. กรอกชื่อ เลือกโมเดล — *Success Fee*: อัตรา % × "มูลค่าหนี้คงเหลือ" · *FLAT*: "ค่าดำเนินการคงที่ (Base Fee) — บาท"
3. ตรวจช่อง "คิดค่าบริการต่อรอบการติดตาม" (ติ๊กไว้ให้ตั้งแต่แรก) · กรอกเหตุผล (≥ 5 ตัวอักษร) → **สร้างเทมเพลต**
- แก้ไข: **⚙️ แก้ไขข้อมูล** → **บันทึกเป็นเวอร์ชันใหม่** — ระบบสร้างเวอร์ชันใหม่เสมอ ไม่ทับของเดิม · เคสจะเก็บค่าบริการตามเวอร์ชัน ณ เวลาที่ "รับเคส"

![](../../shots/R1/R1.02-sf-t1-form.png)

### 2.2 บริษัทไฟแนนซ์
1. การตั้งค่า → บริษัทไฟแนนซ์ → **+ สร้างบริษัท**
2. กรอก ชื่อ, ชื่อย่อ, เลขผู้เสียภาษี 13 หลัก, เทมเพลต, ช่องทางส่งใบกำกับ, จด VAT, รูปแบบราคา ("ราคาก่อน VAT" หรือ "ราคารวม VAT แล้ว"), ลูกค้าหักภาษี ณ ที่จ่าย (ค่าเริ่มต้น 3.00 — เว้นว่าง = "ไม่หัก"), วันตัดรอบ, เครดิต, เหตุผล
- 1 บริษัท = 1 เลขผู้เสียภาษี (ซ้ำจะถูกเตือน)

![](../../shots/R1/R1.09-companies-cards.png)

### 2.3 แผนค่าตอบแทน
1. การตั้งค่า → แผนค่าตอบแทน → **+ สร้างเทมเพลต** → เลือกฝั่ง inhouse/outsource → **เหมาจ่ายรายวัน**
2. กรอก น้ำมัน, เบี้ยเลี้ยง, ที่พักสูงสุด, คอมมิชชั่น, เบี้ยเสี่ยง (เคสไม่สำเร็จ), หัก ณ ที่จ่าย, วันเริ่มมีผล, ติ๊กบังคับใบเสร็จที่พัก → การ์ดขึ้น "v1 · มีผล …"
- ช่องเงินห้ามติดลบ (กรอก 0 ได้) · ค่าน้ำมัน/เบี้ยเลี้ยงคิดวันละครั้งต่อพนักงาน แล้วแบ่งเท่ากันตามจำนวนเคสของวันนั้น

![](../../shots/R1/R1.10-plan-in-form.png)

### 2.4 ทีม
1. การตั้งค่า → ทีมติดตามทรัพย์ → **+ สร้างทีม** → กรอก ชื่อ (ห้ามซ้ำ), ฝั่ง, แผน, หัวหน้า, สถานะ, จังหวัดที่ดูแล (หลายจังหวัดได้ — ใช้เสนอทีมตอนรับเคส), เหตุผล
2. ใส่ผู้จัดการ/หัวหน้าทีม: แถวทีม → **แก้ไข** → **บันทึกการแก้ไข**

![](../../shots/R1/R1.23-teams-done.png)

### 2.5 ผู้ใช้งาน
1. การตั้งค่า → ผู้ใช้งาน → **+ สร้างบัญชี** → เลือกกลุ่ม (ระบบ / Inhouse / Outsource / บริษัทไฟแนนซ์) และบทบาท
2. กรอก ชื่อ, username (ห้ามซ้ำ ไม่สนตัวพิมพ์), อีเมล, รหัสผ่านชั่วคราว 2 ช่อง (≥ 8 ตัว มีตัวเลข), เบอร์ · Inhouse/Outsource ต้องเลือกทีม · บริษัทไฟแนนซ์ต้องเลือกบริษัท
3. ผล: "สร้างบัญชีแล้ว … ต้องเปลี่ยนรหัสผ่านตอนเข้าครั้งแรก" สถานะ "รอผู้ใช้เปลี่ยนรหัส"
- ปุ่มต่อแถว: แก้ไข / ตั้งรหัสผ่าน / ระงับ (ต้องมีเหตุผล) / ลบ

![](../../shots/R1/R1.22-users-inhouse.png)

### 2.6 ตั้งค่าบัญชี/การเงิน

| Tax Profile | ดูอย่างเดียว (3% ภ.ง.ด.53 / 3% ภ.ง.ด.3) · **อัตราของผู้รับเงินชนะอัตราของแผนเสมอ** |
| Payee | **+ เพิ่ม Payee** → ผู้ใช้, เลข 13 หลัก, Tax Profile, ธนาคาร, ชื่อ/เลขบัญชี, เหตุผล → สถานะ "รอยืนยัน" (การเงินยืนยันภายหลัง) |

## 3. ทุกบทบาท: เข้าระบบครั้งแรก

1. ล็อกอินด้วย username + รหัสผ่านชั่วคราวที่ผู้ดูแลแจ้ง → ระบบพาไปหน้า "ตั้งรหัสผ่านใหม่ก่อนเริ่มใช้งาน"
2. กรอก รหัสผ่านชั่วคราว / รหัสผ่านใหม่ / ยืนยันรหัสผ่าน → **บันทึกรหัสผ่านใหม่**
- ก่อนเปลี่ยนรหัสใช้หน้าอื่นไม่ได้ · รหัสใหม่ห้ามซ้ำรหัสเดิม · หลังเปลี่ยนรหัสเก่าใช้ไม่ได้
- หน้าแรก: ผู้ใช้ภายใน → แดชบอร์ด · พนักงานภาคสนาม → แอปภาคสนาม · ผู้ใช้บริษัท → `/portal`
- ออกจากระบบ = ออกทุกอุปกรณ์

## 4. ธุรการ — รับเคส

เมนู: **จัดการเคส → รับเคส** · ปุ่ม `Import ไฟล์` / `+ รับเคส (กรอกมือ)` · KPI ร่าง / รอพิจารณา / ขอข้อมูลเพิ่ม / รับเคสแล้ว · ตัวกรอง สถานะ/ช่องทาง/ไฟแนนซ์/จังหวัด

### 4.1 สร้างเคสด้วยการกรอกมือ
1. `+ รับเคส (กรอกมือ)` → กรอก บริษัท, เลขที่สัญญา, ลูกหนี้ (ชื่อ, สัญชาติ, เลขบัตร, มือถือ), ที่อยู่ปัจจุบัน + ที่อยู่ตามบัตร (พิมพ์รหัสไปรษณีย์ — ถ้าอยู่ในตาราง ระบบเติมจังหวัดให้), ประเภททรัพย์, รุ่น, IMEI, มูลหนี้
2. เลือก **โหมดเอกสาร** (ระบบจำโหมดที่เลือกไว้):
   - **แยกตามประเภท**: สัญญาเช่าซื้อ / บัตรประชาชน / รูปสินค้า (รูป JPG/PNG/WebP/HEIC สูงสุด 8 รูป) · ถ้ารูปสินค้ารวมอยู่ในไฟล์สัญญาแล้ว ให้ติ๊ก **"รูปสินค้ารวมอยู่ในไฟล์สัญญาแล้ว"**
   - **เอกสารชุดเดียว (สแกนรวมเล่ม)**: PDF ไฟล์เดียว **ไม่เกิน 25 MB** (เกินจะถูกปัดทันที) — ส่งตรวจได้โดยไม่ต้องแนบสัญญา/บัตรแยก
3. **บันทึกเคสร่าง** → toast "สร้างเคสร่างแล้ว" สถานะ **ร่าง**

![](../../shots/R2/R2.02-c1-form.png)
![](../../shots/R10v3/g3-02-bundle-12mb-staged.png)

### 4.2 ส่งตรวจ / แก้ไข
- `ส่งตรวจสอบเคส` → สถานะ **รอพิจารณา** · ระบบเสนอทีมตามจังหวัดของ**ที่อยู่ปัจจุบัน** และคำนวณประมาณการรายได้
- ส่งตรวจต้องมี IMEI และเอกสารครบ — ไม่ครบจะขึ้น "เอกสารที่ยังไม่ได้แนบ: …"
- `แก้ไข` → แนบไฟล์ที่ขาด + "หมายเหตุการแก้ไข" → **บันทึกการแก้ไข** · แก้ได้เฉพาะ ร่าง / รอพิจารณา / รอข้อมูลเพิ่ม
- เลขที่สัญญาห้ามซ้ำในบริษัทเดียวกัน — ซ้ำจะขึ้น "เลขที่สัญญาซ้ำ" + ปุ่ม [เปิดเคสเดิม]
- ผลการพิจารณา (รับ/ไม่รับ/ขอข้อมูลเพิ่ม) แจ้งที่กระดิ่ง

![](../../shots/R2/R2.03-c1-doc-incomplete.png)
![](../../shots/R10v3/g4-03-photo-in-contract-ticked.png)

### 4.3 ลบเอกสารที่แนบผิด
1. ในหน้าแก้ไขเคส กด **ลบ** ที่ไฟล์ → หน้ายืนยัน "ลบเอกสารที่แนบ … ระบบเก็บประวัติไว้ตรวจย้อนหลัง" → เหตุผล (ไม่บังคับ) → **ลบเอกสาร**
- ลบได้เฉพาะเคส ร่าง / ขอข้อมูลเพิ่ม · เฉพาะธุรการและ Superadmin
- จะสลับไปโหมดเอกสารชุดได้ต้องลบไฟล์แบบแยกประเภทให้หมดก่อน

![](../../shots/R10v3/g4-04-delete-confirm.png)

### 4.4 นำเข้าเคสจากไฟล์ (แม่แบบ .xlsx)
1. **Import ไฟล์** → "นำเข้าเคสจากไฟล์" → **ดาวน์โหลดไฟล์ตัวอย่าง (.xlsx)** (หรือ CSV) — 2 ชีต (ข้อมูล/คำอธิบาย) หัวคอลัมน์ภาษาไทย ทุกเซลล์เป็นข้อความ (กันเลข 0 นำหน้าและ IMEI เพี้ยน)
2. เลือกบริษัท → เลือกไฟล์ → ระบบจับคู่คอลัมน์อัตโนมัติ → **ตรวจสอบข้อมูล (ไม่บันทึก)** → **ยืนยันนำเข้า N รายการ** → เคสเป็นสถานะร่าง
- ถ้า Excel แปลง IMEI เป็นเลขยกกำลัง (เช่น 3.5E+14) แถวนั้น "ไม่ผ่าน" พร้อมคำแนะนำให้ตั้งรูปแบบเซลล์เป็นข้อความ — ระบบไม่เดาค่าให้

![](../../shots/R10v3/g2-xlsx-preview.png)

## 5. ผู้ตรวจเคส (เจ้าหน้าที่อนุมัติเคส)

### 5.1 พิจารณาเคสใหม่
เมนู: **จัดการเคส → รับเคส** → แถวรอพิจารณา → **พิจารณา**
- modal แสดง สรุปเคส, "ประมาณการรายได้ (ถ้าติดตามสำเร็จ)", "ทีมที่เสนอ" (ป้าย "ระบบเสนอ"), เอกสารแนบพร้อมเวลาอัปโหลด (กดชื่อไฟล์เพื่อดู)
- **รับเคส & ยืนยันทีม** → "รับเคสแล้ว" · ระบบเก็บค่าบริการตามเทมเพลต ณ ตอนนี้ไว้ในเคส
- เปลี่ยนทีม: **ดูทีมอื่นทั้งหมด (N)** → **เลือกทีมนี้** → เหตุผล (บังคับ) → **ยืนยันเปลี่ยนทีม**
- ไม่รับเคส / ขอข้อมูลเพิ่ม: ต้องกรอก "เหตุผล / หมายเหตุ" — ธุรการได้แจ้งเตือนพร้อมเหตุผล
- **เคสเอกสารชุด**: มีป้าย "เอกสารชุด" และต้องติ๊ก "ตรวจเอกสารชุดแล้ว — ในชุดมีสัญญา… และบัตรประชาชน/Passport ลูกหนี้ครบ" ก่อนรับเคส (ถ้าไม่ติ๊ก ข้อความเตือนขึ้นด้านบน modal — เลื่อนขึ้นไปดู)
- เคสที่ตัดสินแล้วตัดสินซ้ำไม่ได้

### 5.2 ตรวจหลักฐานปิดงาน
เมนู: **เคส → ส่งเคส** → "กรองตามสถานะ" (ปิดงานสำเร็จ/ไม่สำเร็จ) → **ดูรายละเอียด** → กล่อง "หลักฐานปิดงาน" (เวลาส่ง, เหตุผลไม่สำเร็จ, บันทึก, รูป/วิดีโอ/จุดเช็คอิน)
- ตีกลับ: **ตีกลับหลักฐานปิดงาน** → เหตุผล (บังคับ) → **ยืนยันตีกลับ** → สถานะ "ต้องแก้ไขหลักฐาน" + แจ้งพนักงาน
- เมื่อคลังรับเครื่องเข้าแล้ว หลักฐาน "ผ่านอัตโนมัติ — ตีกลับไม่ได้แล้ว"

### 6.1 มอบหมายงาน
เมนู: **จัดการเคส → มอบหมายงาน** · KPI พร้อมมอบหมาย / มอบหมายแล้ว (รอรับ) / รับงานแล้ว · เห็นเฉพาะทีมที่ตัวเองดูแล (ผู้จัดการมีตัวกรองทีม)
1. **มอบหมาย** → เลือกการ์ดพนักงาน (แสดง "N เคสในมือ · % สำเร็จ") → **ยืนยันมอบหมาย** → แถว "มอบหมายแล้ว (รอรับ)" + "มอบหมายเมื่อ …"
2. เมื่อพนักงานรับงาน แถวแสดง "รับงานเมื่อ …"
- มอบหมายได้เฉพาะเคส "รับเคสแล้ว" ให้พนักงานในทีมเดียวกัน · 1 เคสมีผู้รับผิดชอบ active 1 คน

### 6.2 เปลี่ยนผู้รับผิดชอบ

  - ยังไม่รับงาน → **ยืนยันเปลี่ยน** เปลี่ยนทันที
  - รับงานแล้ว → **ส่งคำขอเปลี่ยนผู้รับผิดชอบ** → รอพนักงานเดิมยินยอม แถวแสดง "ขอเปลี่ยนเป็น … · เหลืออีก NN นาที" (ระหว่างรอขอซ้ำไม่ได้)
- หมดเวลา → "หมดเวลาแล้ว — รอระบบเปลี่ยนให้อัตโนมัติ" → งานเบื้องหลังโอนให้คนใหม่และแจ้งทั้ง 3 ฝ่าย

1. แถวป้าย "ขั้น 1/2: รอ ผู้จัดการทีมติดตามทรัพย์" → **ดูสูตร** (ที่มาของยอด) → **อนุมัติขั้น 1**
2. ผล: toast "อนุมัติแล้ว" · ป้ายเป็น "ขั้น 2/2: รอ การเงิน" (หรือ "ขั้น 2/3" ถ้าเกิน 5,000 บาท)

## 7. พนักงานภาคสนาม (มือถือ)

หน้าแรก: จำนวนรอรับงาน / กำลังติดตาม / สำเร็จ / % สำเร็จสะสม (คนใหม่ = N/A) / คอมมิชชั่นเดือนนี้ · แท็บ รอรับงาน / รับงานแล้ว / กำลังติดตาม / จบงาน

![](../../shots/R4v3/02-in1-dashboard.png)

### 7.1 รับงานและนัดวัน
1. แท็บ **รอรับงาน** → การ์ด (แสดงเวลามอบหมาย + "จะได้รับถ้าจบงานสำเร็จ ฿…") → **รับงาน** (หรือดูรายละเอียดก่อน)
2. แท็บ **รับงานแล้ว** → **จัดวันที่** → เลือกวันในปฏิทิน (วันที่ผ่านมาแล้วเลือกไม่ได้) → **ยืนยันเลือกวันนี้**
- คำขอเปลี่ยนผู้รับผิดชอบ: แถบ "มีคำขอเปลี่ยนผู้รับผิดชอบ" → **ตอบเลย** (ไม่ยินยอมต้องมีเหตุผล) · ตอบหลังหมดเขตไม่ได้

![](../../shots/R4v3/03-c1-accepted.png)
![](../../shots/R4v3/06-c1-tracking.png)

### 7.2 เช็คอินและบันทึกการติดตาม
1. แท็บ **กำลังติดตาม** → **เริ่มงาน** → เลือกผล สำเร็จ/ไม่สำเร็จ → **แตะเพื่อเช็คอินตำแหน่งปัจจุบัน**
2. ผล: "จุดที่ 1 … · วว/ดด/ปปปป HH:mm · พิกัดล็อกไว้ แก้ไขไม่ได้"
- ต้องเปิดสิทธิ์ตำแหน่ง (ปิดไว้จะขึ้น "เช็คอินไม่สำเร็จ") · ใช้ **บันทึก Draft** เก็บร่างได้ · เน็ตหลุดจะแจ้งและไม่บันทึก

![](../../shots/R4v3/07-c1-checkin.png)

### 7.3 ปิดงาน
- **สำเร็จ**: ต้องมี รูปถ่าย ≥ 1, วิดีโอ ≥ 1, รูปสินค้ายืนยัน ≥ 1 (บันทึกเพิ่มเติมไม่บังคับ) → **ยืนยันปิดงาน** → "ปิดงานเรียบร้อย · ระบบสร้างรายการเบิกให้อัตโนมัติ: คอมมิชชั่น ฿…" · ธุรการได้แจ้ง "รอรับทรัพย์เข้าคลัง"
- **ไม่สำเร็จ**: ไม่ต้องมีรูปสินค้า แต่ต้องเลือกเหตุผล (5 ตัวเลือก — "อื่น ๆ" ต้องอธิบาย) → ได้เบี้ยเสี่ยงตามแผน
- หลักฐานไม่ครบ → กล่องแดง "ยังขาด: …" · ไฟล์ปลอม/ผิดชนิดถูกปฏิเสธและนำออกจากฟอร์ม
- IMEI 15 หลักตรวจที่ขั้นรับเข้าคลัง (พนักงานดู IMEI ได้ในรายละเอียดเคส)

![](../../shots/R4v3/10-c1-closed.png)
![](../../shots/R4v3/16-c3-form.png)

### 7.4 ส่งหลักฐานใหม่หลังถูกตีกลับ
1. กระดิ่ง "หลักฐานปิดงานถูกตีกลับ" → บล็อกส้ม → **แก้ไขหลักฐาน** (dialog แสดงเหตุผล)
2. เพิ่ม/ลบ/แทนไฟล์อย่างน้อย 1 รายการ → **ส่งกลับยืนยันอีกครั้ง**
- ผลการติดตามและจุดเช็คอินถูกล็อกตามรอบเดิม · รายการเบิกของรอบเดิมถูกแทนที่ (ยอดรวมไม่เปลี่ยน)

![](../../shots/R4v3/27-in2-product-v2.png)

### 7.5 เบิกค่าใช้จ่าย
- **ค่าน้ำมันเหมาจ่าย/เบี้ยเลี้ยง ไม่ต้องกรอกเอง** — ระหว่างวันแสดง "รอคำนวณหลังจบวัน" · หลังเที่ยงคืนระบบสร้างให้และแบ่งตามจำนวนเคสของวัน
- คอมมิชชั่นสถานะ "รอยืนยันคืนคลัง" (รอคลังยืนยันส่งมอบ) · เบี้ยเสี่ยงสถานะ "รออนุมัติจ่าย"
- **ค่าที่พัก**: เบิกค่าใช้จ่าย → แท็บ **เบิกแยก** → **+ เบิกที่พัก** → วันที่เข้าพัก, จำนวนเงิน, พักร่วมกับ, ใบเสร็จ (บังคับ), หมายเหตุ → **ส่งคำขอเบิก**
- ถูกตีกลับ: แท็บเบิกแยก → "ถูกตีกลับ ต้องแก้ไขแล้วส่งใหม่" → **แก้ไขและส่งใหม่** → คำชี้แจง → **ส่งกลับเข้าคิวอนุมัติ** (แก้ยอดเองไม่ได้)

2. หลังการเงินอนุมัติและใช้เงินแล้ว: **เคลียร์ยอด** → กรอก "ยอดที่ใช้จริง (บาท)" → ดูสรุป ยืม/ใช้จริง/ต้องคืน → **บันทึกการเคลียร์ยอด** · ใช้เกิน → ระบบสร้าง "คำขอเบิกส่วนเกิน" ให้อัตโนมัติ
- มีเงินทดรองค้างอยู่ (อนุมัติแล้ว/เลยกำหนด) จะขอใหม่ไม่ได้ · เลยกำหนดเคลียร์ระบบแจ้งเตือน

## 8. คลังสินค้า (ธุรการ)

เมนู **คลังสินค้า**: แท็บ รับเข้าคลัง / ในคลัง / รอส่งมอบ / ส่งมอบแล้ว · ขั้นตอน: รับเข้า → นัดวันส่งมอบ (สร้างล็อต) → แนบเอกสาร → ยืนยันส่งมอบ

![](../../shots/R5v2/R5.02-admin-warehouse.png)

### 8.1 รับเข้าคลัง
1. แท็บ **รับเข้าคลัง** → **รับเข้าคลัง** → กรอก **IMEI ที่ตรวจจริง: ตัวเลข 15 หลัก ห้ามมีขีด** → ต้องขึ้นกล่องเขียว "ตรงกับสัญญา"
2. เลือกสภาพ ปกติ / ชำรุด / อุปกรณ์ขาดหาย (สองอย่างหลังต้องกรอกรายละเอียด) → แนบรูป 7 มุม → **ยืนยันรับเข้าคลัง**
- ผล: เครื่องย้ายไปแท็บ "ในคลัง" และหลักฐานปิดงานของเคสผ่านอัตโนมัติ
- IMEI ไม่ตรง: แนวทางคือ**ยกเลิกแล้วตีกลับ** (อย่ากด "ยืนยันรับทั้งที่ IMEI ไม่ตรง" ถ้าไม่แน่ใจ) · ควรกรอก IMEI ที่พบจริงทุกครั้ง
- **ตีกลับ**: เหตุผล (บังคับ) → แถว "ตีกลับ" + ปุ่ม ดูเหตุผล / **รับใหม่** · พนักงานได้แจ้งเตือน

![](../../shots/R5v2/R5.05-c1-photos.png)
![](../../shots/R5v2/R5.03-imei-mismatch.png)

### 8.2 สร้างล็อต (นัดวันส่งมอบ)
1. แท็บ **ในคลัง** → การ์ดบริษัท → **เลือกทุกเครื่องที่พร้อมส่ง** → **นัดวันส่งมอบ (n)** — **1 ล็อต = 1 บริษัทไฟแนนซ์เสมอ**
2. เลือก "ไฟแนนซ์มารับที่คลัง" (วันนัดรับ บังคับ) หรือ "เราจัดส่งไปให้" (ที่อยู่จัดส่ง บังคับ, เลขพัสดุ)
3. **ดูตัวอย่างใบส่งมอบ** → **บันทึกการนัด** → "สร้างล็อต LOT-2569-xxx แล้ว · ใบส่งมอบ DLV-2569-xxx"
- หน้ารายละเอียดล็อต: **Export Excel** / **ใบส่งมอบ PDF** / **แนบเอกสาร & ยืนยัน**

![](../../shots/R5v2/R5.11-preview.png)
![](../../shots/R5v2/R5.13-DLV-2569-003-pdf.png)

### 8.3 แนบเอกสารและยืนยันส่งมอบ
1. มารับที่คลัง: แนบ "ใบเซ็นรับ" · จัดส่ง: แนบใบเซ็นรับ + "หลักฐานจัดส่ง" (แนบใหม่แทนได้ ระบบเก็บเวอร์ชันเก่า)
2. **แนบเอกสาร & ยืนยัน** → "วันเวลาที่ผู้รับมารับจริง" → **ยืนยันส่งมอบสำเร็จ**
- ผล: "ยืนยันส่งมอบ … · ปลดล็อกรายการเบิก N รายการ" · รายการเบิกของเคสในล็อตเข้าคิวอนุมัติ · การเงินได้แจ้งเตือน · รายได้เกิดเมื่อค่าตอบแทนอนุมัติครบ
- **ล็อตที่ยืนยันแล้วแก้ไข/แนบเพิ่มไม่ได้** (ดูเอกสารผ่านปุ่ม "เอกสาร")

## 9. การเงิน

แท็บหลักในเมนู **การเงิน**: ค่าตอบแทน · รออนุมัติ (เงินทดรอง) · ผู้รับเงิน (Payee) · รอบจ่ายเงิน · รายได้และวางบิล · ปรับปรุง

### 9.1 อนุมัติค่าตอบแทนขั้น 2 / ตีกลับ
- **ค่าตอบแทน** → **อนุมัติขั้น 2** · รายการเกิน 5,000 บาทจะไปขั้น 3 ของบริหาร
- **ตีกลับ** → เหตุผล (บังคับ) → "รายการกลับไปเริ่มที่ขั้น 1 ใหม่ทั้งหมด"
- ตัวเลข WHT ในคิวเป็นค่าประมาณ — ยอดหักจริงคำนวณตอนสร้างรอบจ่าย

![](../../shots/R6v3/R6.09-reject-modal-empty.png)

### 9.2 ยืนยันผู้รับเงิน
**ผู้รับเงิน (Payee)** → แถว "รอยืนยัน" → **ยืนยัน** → ตรวจเลขบัญชี/ข้อมูลภาษี → เหตุผล (บังคับ) → **ยืนยันผู้รับเงิน** → "ยืนยันแล้ว · ยืนยันโดย … · วันที่"
- ผู้รับเงินที่ยังไม่ยืนยันทำให้สร้างรอบจ่ายที่มีคนนั้นไม่ได้

![](../../shots/R6v3/40-R6.21-payee-verified.png)

### 9.3 รอบจ่ายเงิน
1. **รอบจ่ายเงิน** → **+ สร้างรอบจ่าย** → ฝั่ง (Inhouse/Outsource) → วันตัดรอบ → ชื่อ → **สร้างรอบจ่าย** → แถวแสดง ยอด / WHT / โอนสุทธิ "รอตรวจสอบ" (**ดูรายการ** เพื่อตรวจ)
2. **สร้างไฟล์โอน** → รูปแบบไฟล์ (ต้องผ่านการ "ทดสอบ" แล้ว) + บัญชีบริษัทที่จ่าย → ตรวจสรุป → เหตุผล → **สร้างไฟล์โอน** → ได้ไฟล์ `PB-…-v1.csv` + Idempotency Key + SHA-256 → **ดาวน์โหลดไฟล์โอน**
   - กดซ้ำ: เตือน "เคยสร้างไฟล์โอนไปแล้ว" — ถ้ายืนยันสร้างซ้ำจะได้ v2 เนื้อหาเดิม key เดิม (v1 ไม่ถูกทับ) — **ระวังโอนซ้ำ**
3. **✓ ยืนยันจ่ายแล้ว** → เหตุผล (บังคับ) → "จ่ายสำเร็จ" · หรือปิดอัตโนมัติเมื่อบัญชีจับคู่ statement ได้
- กติกาภาษี: WHT 3% เมื่อยอดของผู้รับในรอบถึง 1,000 บาท (ต่ำกว่าไม่หัก) · อัตราของผู้รับเงินมาก่อนอัตราของแผน · เงินทดรองไม่หัก WHT
- **50 ทวิ** ออกอัตโนมัติเมื่อรอบจ่าย "จ่ายสำเร็จ" (เลข WHT-2569-xxx) — ไม่ออกให้แถวเงินทดรองหรือแถว WHT 0

### 9.4 เงินทดรอง
- **รออนุมัติ** → ตาราง "เงินทดรองจ่าย" → **อนุมัติ** → **อนุมัติและปล่อยเงิน** · ปฏิเสธต้องมีเหตุผล
- เคลียร์ยอดแทนพนักงานได้จากแถว · ใช้เกิน → คำขอเบิกส่วนเกินเข้าสายอนุมัติปกติ
- **เลยกำหนด**: ระบบเปลี่ยนสถานะทุกวัน · แถวพื้นแดง "เลยกำหนดเคลียร์" + แถบ "ต้องตามเคลียร์ก่อน ผู้ขอจะเบิกรอบใหม่ไม่ได้" + แจ้งเตือนทั้งพนักงานและการเงิน

### 9.5 วางบิล

2. **ส่งวางบิล** → เหตุผล → **ยืนยันส่งบิล** → "ส่งบิล วว/ดด/ปปปป" · การ์ด "ยอดค้างรับ (AR)"

- **ล็อก**: บัญชี → **รอบส่งบัญชี** → **ล็อกงวด** → เหตุผล → **ยืนยันล็อกงวด** → "ปิดรอบแล้ว" · หลังล็อกทุกการแก้ไขที่กระทบยอดถูกปัด ต้องทำ Adjustment แทน

- การลดค่าบริการหลังออกใบกำกับแล้ว สำนักงานบัญชีต้องออกใบลดหนี้นอกระบบ
