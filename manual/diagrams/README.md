## วิธีอ่านสัญลักษณ์

### ผังการทำงาน / ผังงานราย role (flowchart)

| สัญลักษณ์ | ความหมาย |
|---|---|
| กล่องสี่เหลี่ยม `[ ]` | ขั้นตอนงาน / การกดปุ่ม |
| ◇ `{ }` | จุดตัดสินใจ — ลูกศรที่ออกจากจุดนี้มีข้อความบอกเงื่อนไข |
| วงรีปลายมน `([ ])` | จุดเริ่ม / จุดจบ / ส่งต่อไปโมดูลอื่น |
| กล่องสีส้ม ⏳ | **ต้องรอ role อื่น** — ใต้ผังมีลิงก์ไปกลุ่มนั้น |
| 📍 | ทำที่เมนูไหน (ชื่อเมนู → แท็บ ตามหน้าจอจริง) |
| ลูกศรทึบ `-->` | ลำดับปกติ |
| ลูกศรประ `-.->` | ทางเลือก / กรณีพิเศษ / ความสัมพันธ์ทางอ้อม |
| กรอบ (subgraph) | แผนกหรือผู้รับผิดชอบ (swimlane) |

### ผังสถานะ (stateDiagram)

| สัญลักษณ์ | ความหมาย |
|---|---|
| กล่องมุมมน | สถานะ — ชื่อตรงกับป้ายสถานะบนหน้าจอ |
| ● (`[*]`) ต้นลูกศร | จุดเริ่ม — ข้อมูลถูกสร้าง |
| ◉ (`[*]`) ปลายลูกศร | สิ้นสุด — เปลี่ยนสถานะต่อไม่ได้แล้ว |
| ข้อความบนลูกศร | ปุ่มหรือเหตุการณ์ที่ทำให้สถานะเปลี่ยน · "(เหตุผล)" = ต้องกรอกเหตุผลทุกครั้ง |

| เส้นประ | ดูอย่างเดียว |

### ตาราง use case × role

✅ ทำ/จัดการได้ · 👁 ดูอย่างเดียว · — ไม่เห็น · 🔒 ล็อก · ⓢ จำกัดขอบเขต (ทีมตัวเอง / งานตัวเอง / บริษัทตัวเอง)

## หลักการที่ผังทุกผังใช้ร่วมกัน

- ชื่อสถานะ ปุ่ม และเมนู ใช้คำเดียวกับที่ผู้ใช้เห็นบนหน้าจอ
- วันที่บนหน้าจอเป็น **พ.ศ.** เสมอ · เงินแสดงเป็นบาท
- เคสที่ **ปิดงานสำเร็จ** ต้องผ่านคลังและล็อตส่งมอบที่ยืนยันแล้วก่อน รายได้จึงจะเกิด — เคสที่ **ปิดงานไม่สำเร็จ** ไม่ผ่านคลัง
- งวดบัญชีที่ **ปิดรอบแล้ว** แก้ข้อมูลตรงไม่ได้ ต้องทำ **รายการปรับปรุง**
- ระบบเตรียมข้อมูลให้สำนักงานบัญชี — การลงบัญชีและยื่นภาษีจริงทำนอกระบบ
- ถ้าเอกสารสเปคกับโค้ดปัจจุบันไม่ตรงกัน ผังยึด **โค้ดปัจจุบัน** และจดไว้ท้ายแต่ละไฟล์
