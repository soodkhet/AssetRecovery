# ด่าน 7/7 — เบราว์เซอร์จริงบนฐาน dev (หลัง merge ด่าน 1–6)

> รันโดย orchestrator บนเครื่อง (ไม่ใช่ worktree) · ฐาน `assetrecovery_dev` ที่ seed ด้วยสคริปต์ Final (`scripts/seed-final/`) · dev server `http://localhost:3000` (เปิด/รีสตาร์ทด้วย `~/bin/dev asset`) · เครื่องมือ Playwright ใน `uat/bin/lib.mjs` (Chrome headless) · persona จาก `uat/personas.json` (**ห้ามพิมพ์รหัสผ่านลง log/รายงาน**) · รายงาน `uat/report/FINAL-7-browser.md` + ภาพใน `uat/shots/final/`

ก่อนเริ่ม: snapshot ฐาน dev (`final-seeded`) เพื่อย้อนได้ · Storage/Supabase Auth ที่เขียนเพิ่ม = ข้อมูลตัวอย่าง จดรายการไว้ลบก่อน go-live

1. **ทุก role × ทุกเมนูที่เห็น** (14 persona + ผู้ใช้บริษัท Portal): เปิดได้ ไม่มี 5xx · ไม่มี console error · ไม่มีปี ค.ศ. · ไม่มีเลขอ้างอิงสเปคบนจอ · loading/empty/error ไม่ใช่หน้าขาว
2. **คิวตาม golden:** ทุก role มีงานในคิวตามตารางความครอบคลุม · ตัวเลขแดชบอร์ด = จำนวนแถวหน้าปลายทาง · ผู้จัดการเห็นเฉพาะทีม
3. **Flow สำคัญกดจริงครบสาย** (ตามแถวในตารางความครอบคลุม): ส่งเคส → อนุมัติ → มอบหมาย → ภาคสนาม (viewport มือถือ 375×812) → ปิดงาน → คลัง → ล็อต confirm → รายได้ → วางบิล → รับเงิน + ใบเสร็จ/ใบกำกับ → เบิก/อนุมัติ → รอบจ่าย → ไฟล์โอน → จ่ายสำเร็จ → 50 ทวิ → ปิดงวด → Export Pack → Portal เห็นผล
4. **ตัวเลขบนจอ = golden** ทุกจุดที่ตารางระบุ (ถึงสตางค์) · PDF ที่ดาวน์โหลดจริงตรง golden + หัวกระดาษ/ข้อความท้าย/ลายเซ็นตามค่าตั้ง
5. **สิทธิ์จากหน้าจอ:** ปุ่มที่ไม่มีสิทธิ์ซ่อน/ปิดตาม spec · พิมพ์ URL ตรงของหน้าที่ไม่มีสิทธิ์ = ถูกกัน
6. **ค่าตั้งมีผล:** เปลี่ยนค่าตั้งที่มีหลายแบบ (เทมเพลต/โหมดภาษี/ค่าเริ่มต้นตามประเภท) แล้วเห็นผลในเอกสาร/การคำนวณถัดไป และเอกสารเก่าไม่ขยับ
7. **Validation:** ฟอร์มหลักกรอกผิด → ข้อความไทยชัด ไม่ 500 (IMEI ผิด · เงินติดลบ · เหตุผลว่าง)
