# ด่าน 5/6 — ความครบของ UI (ทุกเมนู/ปุ่มใช้งานได้จริง)

**ที่มา:** บทเรียนจากโปรเจกต์ก่อน — UAT พบเมนูตั้งค่าหลายหน้าเป็น placeholder ("จะถูก implement ใน Phase X") ทั้งที่เฟสนั้นปิดไปแล้ว ด่านนี้มีไว้กันเคสแบบนี้หลุดอีก

ไล่ตรวจ **ทุก route/เมนู** แล้วรายงานว่าอันไหน "ใช้งานได้จริง" vs "ยังเป็นโครง":

1. **เทียบเมนูกับหน้าจริง:** เอา Top Nav 7 เมนู + sub-tabs ทุกโมดูลจาก `docs/06` §7.1.1 มาไล่กับ route จริงใน `app/`
   - หา placeholder ทุกตัว (หน้าที่ render ข้อความว่า "กำลังพัฒนา"/"Phase N")
   - หาปุ่ม/ฟีเจอร์ที่ `disabled` ถาวรโดยไม่ผูกกับสถานะข้อมูล
   - ทุกเมนูที่ผู้ใช้กดได้ต้องมีหน้าจริง — ถ้ายังไม่ทำ **ห้ามปล่อยให้กดเข้าไปเจอหน้าเปล่า** (ซ่อนเมนูตามสิทธิ์ หรือระบุสถานะชัดเจน + บันทึกเป็น task ใน PROGRESS.md)
2. **Role × Menu Visibility Matrix (`06` §7.2):** เข้าด้วยแต่ละ role แล้วเมนูที่เห็นตรงกับ matrix · เคสพิเศษ: ปุ่ม assign ของ Supervisor ที่ปิดด้วย settings ต้อง **hide ไม่ใช่ disabled** (`40` §7.2)
3. **Design system (`04` §8.1):** badge ใช้ mapper กลาง 10 กลุ่มสี ไม่มีสีสุ่ม · card/table/button ใช้ class มาตรฐาน · font Inter + Noto Sans Thai · เลขอ้างอิง/รหัสใช้ `font-mono`
4. **สถานะหน้าจอครบ 3 แบบ:** ทุกหน้ามี loading / empty / error state จริง (ไม่ใช่หน้าขาว)
5. **วันที่:** ทุกจุดบนหน้าจอเป็น **พ.ศ.** `DD/MM/YYYY` — เจอ ค.ศ. ที่ไหน = bug (`DISPLAY_CE_YEAR`)
6. **Mobile:** Field Tracker บนมือถือกับ desktop ใช้ logic เดียวกัน 100% (`41` §11) · Client Portal mobile ใช้ได้จริง
7. **CRUD ครบวงจร:** หน้าที่มี list ต้องมีทางสร้าง/แก้/ลบ หรือระบุชัดว่าอ่านอย่างเดียวโดยตั้งใจ

**รายงานเป็นตาราง:** `| เมนู/route | สถานะ (✅ ใช้ได้ / ⚠️ โครงเปล่า / ❌ พัง) | หลักฐาน (ไฟล์:บรรทัด) | ต้องทำอะไรต่อ |`

**การแก้:**
- งานเล็ก (ลิงก์เสีย/ปุ่มไม่ผูก/ขาด wiring) → แก้ให้เลย + test
- ฟีเจอร์ใหญ่ที่ยังไม่ทำ → **ห้ามสร้างเองในด่านนี้** ให้เพิ่มเป็น task ใหม่ใน PROGRESS.md (พร้อมสเปคย่อ + ชี้ backend ที่มีอยู่แล้ว) แล้วรายงานว่าเพิ่มอะไรบ้าง
