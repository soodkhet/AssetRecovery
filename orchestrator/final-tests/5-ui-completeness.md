# ด่าน 5/5 — ความครบของ UI (ทุกเมนู/ปุ่มใช้งานได้จริง)

**ที่มา:** UAT พบว่าเมนูตั้งค่า 3 หน้าเป็น placeholder ("จะถูก implement ใน Phase X") ทั้งที่เฟสนั้นปิดไปแล้ว — ด่านนี้มีไว้กันเคสแบบนี้หลุดอีก

ไล่ตรวจ **ทุก route/เมนู** ทั้งหลังบ้านและหน้าบ้าน แล้วรายงานว่าอันไหน "ใช้งานได้จริง" vs "ยังเป็นโครง":

1. **หลังบ้าน (admin):** เทียบ `navConfig` (เมนูที่โชว์ผู้ใช้) กับ `pages/registry.tsx` (หน้าที่ implement จริง)
   - หา placeholder ทุกตัว (เช่น map `"settings:xxx": "Phase N"` หรือ component ที่ render ข้อความว่า "จะถูก implement")
   - หาปุ่ม/ฟีเจอร์ที่ `disabled` แบบถาวรโดยไม่มีเหตุผลผูกกับสถานะข้อมูล
   - ทุกเมนูที่ผู้ใช้กดได้ ต้องมีหน้าจริงที่ทำงานได้ — ถ้ายังไม่ทำ **ห้ามปล่อยให้กดเข้าไปเจอหน้าเปล่า** (ต้องซ่อนเมนู หรือมีสถานะ "กำลังพัฒนา" ที่ชัดเจน + บันทึกเป็น task ใน PROGRESS.md)
2. **หน้าบ้าน (public):** ทุก route ใน `apps/web/app` render ได้ ไม่ 404/error · ลิงก์ใน header/footer/nav ไปที่หน้าที่มีจริง
3. **ตรวจย้อนกับสเปค:** เมนู/หน้าที่ docs/09 (routes) และ docs/16 ระบุไว้ มีครบไหม — ที่ขาดคืออะไร
4. **CRUD ครบวงจร:** หน้าที่มี list ต้องมีทางสร้าง/แก้/ลบ (หรือระบุชัดว่าอ่านอย่างเดียวโดยตั้งใจ เช่น provinces)

**รายงานเป็นตาราง:** `| เมนู/route | สถานะ (✅ ใช้ได้ / ⚠️ โครงเปล่า / ❌ พัง) | หลักฐาน (ไฟล์:บรรทัด) | ต้องทำอะไรต่อ |`

**การแก้:**
- ถ้าเป็นงานเล็ก (ลิงก์เสีย/ปุ่มไม่ผูก/หน้าขาด wiring) → แก้ให้เลย + test
- ถ้าเป็นฟีเจอร์ใหญ่ที่ยังไม่ทำ → **ห้ามสร้างเองในด่านนี้** ให้เพิ่มเป็น task ใหม่ใน PROGRESS.md (พร้อมสเปคย่อ + ชี้ backend ที่มีอยู่แล้ว) แล้วรายงานว่าเพิ่มอะไรบ้าง
