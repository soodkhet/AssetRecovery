# ด่าน 5/7 — ความครบของ UI (ทุกเมนู/ปุ่มใช้งานได้จริง) — ระดับโค้ด

> อ่าน `0-common.md` ก่อน (ฐาน `assetrecovery_test6` · รายงาน `uat/report/FINAL-5-ui.md`) · ด่านนี้ตรวจจากโค้ด/route + test · การกดจริงบนเบราว์เซอร์อยู่ด่าน 7

**ที่มา:** โปรเจกต์ก่อนเจอเมนูตั้งค่าเป็น placeholder ทั้งที่เฟสปิดแล้ว + ค่าตั้งที่บันทึกได้แต่ไม่มีผล (หนี้ #4 → U122)

1. **เมนู ↔ หน้าจริง:** Top Nav + sub-tabs ทุกโมดูลจาก `docs/06` §7.1.1 + เมนูธุรการ (U71) + ข้อมูลองค์กร (U99) + เทมเพลตเอกสาร (U122) + ตัวอย่างเอกสาร (U104) + แดชบอร์ด (6.6) + Portal (`97`) ไล่กับ `app/` — ไม่มี placeholder ("กำลังพัฒนา"/"Phase N") · ไม่มีปุ่ม `disabled` ถาวร
2. **ค่าตั้งต้องมีผลจริง:** ทุกช่องในหน้าตั้งค่า (22+ แท็บ) ต้องมีโค้ดฝั่งใช้งานอ่านค่านั้น (grep consumer นอก route ตั้งค่า) — ช่องที่ไม่มี consumer = ❌ · ทุกค่าตั้งการเงิน/บัญชีมี `<SettingHelp>` (U108)
3. **Role × Menu Visibility (`06` §7.2):** แต่ละ role เห็นเมนูตาม matrix (ผู้จัดการ/หัวหน้าทีม U22 · บริหาร Export ใบส่งมอบ U23) · ปุ่ม assign ของ Supervisor ที่ปิดด้วย settings = **hide** (`40` §7.2) · widget แดชบอร์ดตาม role + scope ทีม (U115/U116)
4. **Design system (`04` §8.1):** statusBadge mapper กลาง 10 กลุ่มสี · class มาตรฐาน · Inter + Noto Sans Thai · เลขอ้างอิงใช้ `font-mono`
5. **สถานะหน้าจอ 3 แบบ:** ทุกหน้ามี loading / empty / error state
6. **วันที่ พ.ศ. `DD/MM/YYYY`** ทุกจุด (ยกเว้น `<input type="date">`) · **ข้อความบนจอไม่มีเลขอ้างอิงสเปค** (`lib/ui/no-spec-refs.test.ts` ผ่าน + grep ส่วนที่ test ไม่ครอบ)
7. **Mobile:** Field Tracker mobile/desktop logic เดียวกัน (`41` §11) · Portal mobile
8. **CRUD ครบวงจร** หรือระบุชัดว่าอ่านอย่างเดียวโดยตั้งใจ

รายงาน: `| เมนู/route | ✅ / ⚠️ โครงเปล่า / ❌ พัง | หลักฐาน (ไฟล์:บรรทัด) | ต้องทำต่อ |` · งานเล็กแก้เลย + test · ฟีเจอร์ใหญ่ → บันทึกเป็นงานใหม่ในรายงาน ห้ามสร้างเอง
