## 1. Summary

รวมสูตรคำนวณทางการเงิน/บัญชีทั้งหมดของระบบไว้ในที่เดียว เป็น single source of truth สำหรับทีมพัฒนา — ป้องกันสูตรไม่ตรงกันระหว่างโมดูล

## 2. Purpose

เมื่อ implement จริง นักพัฒนาควรอ้างอิงไฟล์นี้สำหรับ logic การคำนวณ แทนการไปเดาเองจากแต่ละหน้าจอ

## 3. In Scope

สูตรคำนวณทั้งหมดที่เกี่ยวกับ: ค่าตอบแทนทีมงาน (ไฟล์ 11), รายได้จากบริษัทไฟแนนซ์ (ไฟล์ 12/19), ภาษีหัก ณ ที่จ่ายและ VAT (ไฟล์ 13), ยอดจ่ายสุทธิ (ไฟล์ 17), กำไรขั้นต้น (ไฟล์ 21)

## 4. Out of Scope

- State machine ของแต่ละ entity (ไฟล์ 23)
- Validation rules ที่ไม่ใช่สูตรคำนวณ (ไฟล์ 24)

### 6.1 ค่าน้ำมัน (Fuel) — โหมด PER_KM (อ้างอิงไฟล์ 11, 41 §6.4.2)

```
ระยะทางจริง = คำนวณจาก travel_origin → checkin[1] → checkin[2] → ... → checkin[n]

```

### 6.5 รายได้จาก Service Fee — Model SUCCESS_FEE (อ้างอิงไฟล์ 12, 19)

```
หมายเหตุ timing: Revenue เกิดเมื่อ expense ของเคสนั้นเข้าสู่ approved แล้วเท่านั้น
                  (ไม่ใช่ทันทีที่ outcome = closed_success — ดูไฟล์ 19 §6.1 สำหรับเหตุผลเต็ม)

ถ้า outcome = closed_fail: revenue_gross = fail_fee ?? 0   (§6.7.1 — มติ U165)
ถ้า outcome = closed_success และ expense.status = approved:
  ฐานคำนวณ = debt_amount  (ยอดหนี้คงเหลือ — ฐานเดียว ตามมติ PO U126)
  revenue_gross = ฐานคำนวณ × (rate / 100)
```

### 6.6 รายได้จาก Service Fee — Model FLAT (อ้างอิงไฟล์ 12)

```
ถ้า outcome = closed_success: revenue_gross = base
ถ้า outcome = closed_fail:    revenue_gross = fail_fee ?? 0   (§6.7.1 — มติ U165)
```

### 6.7 รายได้จาก Service Fee — Model HYBRID (อ้างอิงไฟล์ 12)

```
ถ้า outcome = closed_success:
  ฐานคำนวณ = debt_amount (ยอดหนี้คงเหลือ — ฐานเดียว ตามมติ PO U126)
  revenue_gross = base + ฐานคำนวณ × (rate / 100)
ถ้า outcome = closed_fail:
  revenue_gross = fail_fee ?? 0   (§6.7.1 — ไม่ได้ base/rate)
```

#### 6.7.1 กรณีไม่สำเร็จ — ยอดแยกทุกโมเดล (มติ PO U165)

```
fail_fee = snapshot cases.service_fee_fail_fee_satang (สตางค์ · NULL = ไม่เรียกเก็บ)
ถ้า outcome = closed_fail:
  fail_fee = NULL ⇒ ไม่เกิด Revenue (`19` §6.1 model_excludes_fail)
  fail_fee ≠ NULL ⇒ revenue_gross = fail_fee   (ไม่ผ่านคลัง)
ตัวอย่าง: FLAT base 1,500 / fail_fee 300 ⇒ สำเร็จ 1,500 · ไม่สำเร็จ 300
ข้อมูลก่อนมติ: charge_on_fail = true (FLAT/HYBRID) ⇒ fail_fee = base · นอกนั้น ⇒ NULL (ผลเท่าเดิมทุกบาท)
```

> **รอบการติดตาม (มติ PO U125)** — สูตร §6.5–6.7 คิดแยกต่อ (เคส, `tracking_round`) **ทุกรอบอิสระเสมอ** ไม่มีสวิตช์ · รอบใหม่ (recycle) ใช้ snapshot ค่าบริการของรอบนั้น + `debt_amount` ณ รอบนั้น → รายได้ใบใหม่ ไม่หักกลบกับรอบก่อน

### 6.8 VAT (อ้างอิงไฟล์ 13 §6.5, 19 §6.3)

```
หาอัตรา VAT ที่ effective ณ revenue_date:
  vat_rate = vat_rate_history ที่ effective_from <= revenue_date <= (effective_to หรือ ยังไม่มีวันสิ้นสุด)

ถ้า บริษัทไฟแนนซ์ vat_mode = no_vat:        vat_amount = 0
ถ้า vat_mode = exclude_vat (ราคาก่อน VAT แยกบรรทัด):
  vat_amount = revenue_gross × (vat_rate / 100)
  total_amount = revenue_gross + vat_amount
ถ้า vat_mode = include_vat (ราคารวม VAT):
  vat_amount = revenue_gross × vat_rate / (100 + vat_rate)
  total_amount = revenue_gross  (ราคาที่ตกลงรวม VAT แล้ว ไม่บวกเพิ่ม)

snapshot vat_rate_used ไว้ที่ Revenue Record เสมอ ไม่ดึงอัตราสดทุกครั้ง
```

#### 6.8.2 ยอดบนใบเสร็จรับเงิน/ใบกำกับภาษี (มติ PO 06/10/2569 U95 · U96 #9 · ม.78/1(2))

ความรับผิด VAT ของค่าบริการเกิดเมื่อรับชำระ ⇒ ยอดบนใบ = ยอดที่รับ (pure `receiptInvoiceAmounts()` — `lib/sales/receipt-invoice.ts`):

```
paid               = cash_receipts.amount_satang + wht_withheld_by_customer_satang   (ภาษีที่ลูกค้าหัก = การรับชำระ)
rate               = vat_rate_history ณ วันรับเงิน (ห้าม hardcode · ไม่ใช่ snapshot รายได้ตอนวางบิล)
remaining_before   = sales_records.total_before_vat_satang − Σ ก่อน VAT ของใบ active ของรอบ (รวมใบกำกับแบบเดิม)
remaining_before ≤ 0 หรือ paid ≤ 0 ⇒ TAX_INVOICE_NOTHING_TO_INVOICE
remaining_vat      = rate เท่ากับอัตราใบแจ้งหนี้และใบก่อนหน้าทุกใบ ? sales_records.vat_satang − Σ VAT ใบ active
                                                                  : round_half_up(remaining_before × rate / 100)
fee                = billing_batches.bank_fee_written_off_satang (§6.11.1 · ไม่มีการตัด = 0)       (มติ PO U169)
paid + fee ≥ remaining_before + remaining_vat ⇒ ใบปิดยอด: ก่อน VAT = remaining_before · VAT = remaining_vat
                                              · ส่วนเกิน = max(0, paid − remaining) ไม่ออกเอกสาร
                                              · ค่าธรรมเนียมบนใบ = max(0, remaining − paid)
มิฉะนั้น (รับบางส่วน)                ⇒ VAT = round_half_up(paid × rate / (100 + rate)) · ก่อน VAT = paid − VAT (ไม่นำ fee มาใช้)
```

- **มติ PO U169 (BUG-179)** — บิลที่ปิดด้วยการตัดส่วนต่างเป็นค่าธรรมเนียมธนาคาร (U144/U163) ออกใบ**เต็มยอดบิล** สถานะ "รับชำระครบ" · VAT จากมูลค่าบริการเต็ม (ม.79 — ค่าธรรมเนียมที่ธนาคารหักเป็นค่าใช้จ่ายของเรา ไม่ใช่ส่วนลด ไม่เข้าเหตุออกใบลดหนี้ ม.86/10) · ใบรับบางส่วนก่อนหน้าไม่ดูดส่วนต่าง — ใบที่ปิดยอดเป็นผู้รับส่วนต่างเสมอไม่ว่าออกใบลำดับใด ⇒ ผลรวมทุกใบ = ใบแจ้งหนี้ · PDF พิมพ์แถว "หัก ค่าธรรมเนียมการโอน (ผู้รับเงินเป็นผู้รับภาระ)" = ยอดรวม − เงินโอน − ภาษีลูกค้าหัก และไม่มียอดคงค้าง · ป้ายสมมติฐาน `bank_fee_full_tax_invoice` (รอนักบัญชียืนยัน)
  > ตัวอย่าง BL-2569-011: ก่อน VAT 1,750.03 + VAT 122.50 = 1,872.53 · เงินโอน 1,800.00 · ลูกค้าหัก 52.50 · ตัดส่วนต่าง 20.03 ⇒ ใบเดียว 1,750.03 / 122.50 / 1,872.53 (เดิมออก 1,731.31 / 121.19 / 1,852.50 "รับชำระบางส่วน" ค้าง 20.03)

- ผลรวมทุกใบของรอบ (อัตราไม่เปลี่ยน) = ยอดใบแจ้งหนี้เป๊ะ (ไม่มีเศษสตางค์หลุด) · อัตราเปลี่ยน ⇒ ยอดรวม VAT ที่ต้องชำระเปลี่ยนตามอัตราใหม่ (ลูกค้าโอนตามใบแจ้งหนี้เดิม = ยังไม่ปิดยอด)
- VAT = 0 หรือรอบ `no_vat` ขณะผู้ขายจด VAT ⇒ `TAX_INVOICE_NO_VAT_COMPANY` (U96 #3)
- ข้อจำกัดที่รู้: Adjustment ก่อนรับเงิน (ยังไม่มีใบกำกับ) ไม่เปลี่ยนฐานใบแจ้งหนี้ — ฐานคงเป็นยอดใบแจ้งหนี้ ณ วันวางบิล (ส่งนักบัญชียืนยัน)

#### 6.8.1 VAT ของใบลดหนี้ (มติ PO 05/10/2569 U14 · มติบัญชี B1 · ม.86/10)

ใบลดหนี้ออกโดยสำนักงานบัญชีนอกระบบ — ระบบบันทึกยอดตามเอกสารแล้วตรวจความสอดคล้อง:

```
vat_rate_pct_used    = อัตรา VAT บนใบที่อ้างถึง (tax_invoices.vat_rate_pct_used — U96 #9)
                       ใบกำกับแบบเดิมที่ไม่มีอัตราบนใบ ⇒ revenues.vat_rate_pct_used ของรอบวางบิล (ต้องมีอัตราเดียว)
expected_vat         = round_half_up(amount_before_vat × vat_rate_pct_used / 100)   (ตัวคูณกลาง pctOfSatang)
vat_amount           = ยอดตามเอกสาร (ไม่กรอก = expected_vat) · |vat_amount − expected_vat| ≤ 1 สตางค์
total_amount         = amount_before_vat + vat_amount   (คิดที่ server เสมอ)
ยอดคงเหลือของใบกำกับ = ยอดใบกำกับ − Σ ใบลดหนี้ที่ active (ทั้งก่อน VAT และยอดรวม) — ใบลดหนี้ใหม่ห้ามเกินยอดคงเหลือ
ยอดค้างของรอบ       = ยอดตามเอกสารของรอบวางบิล − (รับแล้ว + ภาษีลูกค้าหัก + ค่าธรรมเนียมที่ตัด)   (§6.11 · U171)
ใบลดหนี้ใหม่: total_amount ≤ ยอดค้างของรอบ ณ ตอนบันทึก — เกิน ⇒ CREDIT_NOTE_EXCEEDS_OUTSTANDING (บิลชำระครบ = ลดไม่ได้)
ลดหนี้ได้สูงสุด (รวม VAT) = max(0, min(ยอดคงเหลือของใบกำกับ (รวม), ยอดค้างของรอบ))
```

### 6.9 ภาษีหัก ณ ที่จ่าย (WHT) (อ้างอิงไฟล์ 13 §6.4, 17, 18)

> **WHT Rate Priority Rule** (ดูรายละเอียดเต็มที่ไฟล์ 18 §6.3):
> Payee Profile level ชนะ Plan level เสมอ
> ```
> WHT rate = PayeeProfile.tax_profile.wht_rate        (ถ้ามี — ตั้งรายคน)
>          = ค่าเริ่มต้นตามประเภทผู้รับ.wht_rate        (ฝั่ง × ชนิดผู้รับ — ไฟล์ 13 §6.4.3 · มติ PO U121 · นับเป็นฝั่ง payee)
>          = CompensationPlan.wht_rate                 (fallback + warning ถ้าไม่มีสองข้อแรก)
>          = ไม่มีอัตรา                                 (ไม่ throw: คิวอนุมัติเตือนต่อแถว · รอบจ่ายบล็อก WHT_RATE_MISSING)
> ```
> resolve **เฉพาะรายการที่อยู่ในฐาน WHT** (§6.9.1) — รายการนอกฐานไม่ใช้อัตรา (ภาษี 0 · `whtPctUsed = 0`) · รายการในฐานที่ไม่มีอัตรา
> ไม่นับเข้าฐานรวม/เกณฑ์ (ภาษี 0) และติดธง `rateMissing` ให้ผู้เรียกบล็อก/เตือน (`resolveWhtRate()` คืน `null` · `calculatePayeeBatchWht()`)

```
ดึง tax_profile ของ Payee นั้น (ไฟล์ 18) → ได้ wht_rate, wht_basis, wht_min_threshold

ฐานหัก = gross_amount                           ถ้า wht_basis = before_vat (มาตรฐานทั่วไป)
       = gross_amount + vat_amount               ถ้า wht_basis = gross_amount (ไม่ปกติ แต่รองรับได้)

เกณฑ์ขั้นต่ำเทียบ "ต่อ payee ต่อรอบจ่าย" (มติ PO 03/10/2569 — UAT Q5):
  ฐานรวม_payee = SUM(ฐานหัก) ของทุกรายการค่าตอบแทนของ payee นั้นในรอบจ่ายเดียวกัน
                 (ไม่รวมเงินทดรองจ่าย — ไม่ใช่เงินได้ ไม่หัก WHT)

ถ้า ฐานรวม_payee < wht_min_threshold (ค่าเริ่มต้น 1,000 บาท): wht_amount = 0 ทุกรายการของ payee
ถ้า ฐานรวม_payee >= wht_min_threshold:
  จัดกลุ่มรายการของ payee ตาม wht_rate ที่ resolve ได้ (ปกติกลุ่มเดียว — อัตราจาก Tax Profile ของ payee)
  wht_กลุ่ม = round(ฐานรวม_กลุ่ม × (wht_rate / 100))   ปัดครั้งเดียวต่อกลุ่ม (ค่าเริ่มต้น wht_rate = 3% มาตรา 40(7)/40(8))
  กระจาย wht_กลุ่ม ลงแต่ละรายการตามสัดส่วนฐานหัก แบบ largest remainder:
    ส่วนแบ่ง_i = floor(wht_กลุ่ม × ฐาน_i / ฐานรวม_กลุ่ม)
    เศษที่เหลือ (wht_กลุ่ม − SUM(ส่วนแบ่ง)) แจกทีละ 1 สตางค์ให้รายการที่เศษหารมากสุดก่อน (เสมอกัน = รายการที่มาก่อน)
  ⇒ SUM(wht_amount ของรายการ) = wht_กลุ่ม เป๊ะ ไม่มีเศษสตางค์หาย

net_amount = gross_amount - wht_amount   (ทุกแถว)
```

> **เกณฑ์สะสมต่อเดือน (staging E-054 · มติ PO 10/10/2569 — ค่าเริ่มต้น · `wht_policy_history.threshold_scope = monthly_cumulative`)**
> ```
> เดือน = เดือนปฏิทินไทยของวันสร้างรอบจ่าย · นับเฉพาะรายการค่าตอบแทนในฐาน หมวด 40(8) ของรอบที่ไม่ถูกยกเลิก
> ฐานก่อนหน้า        = SUM(ฐานของรายการผู้รับในรอบก่อน ๆ ของเดือน)          (เงื่อนไข (2)/(3): gross − ภาษีที่ออกให้)
> ฐานก่อนหน้ายังไม่หัก = SUM(ฐานของรายการที่ wht = 0) − SUM(wht_carried_base_satang ของเดือน)
> ถ้า ฐานรวม_payee(รอบนี้) + ฐานก่อนหน้า < wht_min_threshold ⇒ ไม่หัก
> ไม่งั้น: ฐานที่ยกมา = ฐานก่อนหน้ายังไม่หัก (จำกัดไม่ให้ภาษีเกินฐานรอบนี้ — เงื่อนไข (1))
>          กระจายฐานที่ยกมาลงกลุ่มอัตรา/รายการตามสัดส่วนฐาน (largest remainder) → wht_carried_base_satang
>          wht_กลุ่ม = round((ฐานรวม_กลุ่ม + ฐานยกมา_กลุ่ม) × wht_rate/100) แล้วกระจายตามสัดส่วนฐานเหมือนเดิม
> ใบ 50 ทวิ: เงินได้ = gross + wht_carried_base_satang ของรายการในใบ (ภ.ง.ด. รวมจากใบ ⇒ ตรงกันเอง)
> ```
> ตัวอย่าง: 3% เกณฑ์ ฿1,000 · รอบ 1 จ่าย ฿600 ไม่หัก · รอบ 2 จ่าย ฿500 ⇒ หัก ฿33 (3% ของ ฿1,100) ใบ 50 ทวิ เงินได้ ฿1,100 · รอบ 3 จ่าย ฿200 ⇒ หัก ฿6
> ค่าตั้ง `per_batch` = สูตรต่อรอบด้านบน (รอบก่อน E-054 snapshot NULL = ต่อรอบ) · pure: `calculatePayeeBatchWht({ monthToDate })` + `monthToDateByPayee()`

> ตัวอย่าง: payee อัตรา 3% มี 3 รายการ × ฿600 ในรอบเดียว → ฐานรวม ฿1,800 ≥ ฿1,000 → หักรวม ฿54 (รายการละ ฿18) · ถ้ามี 2 รายการ × ฿350 → ฐานรวม ฿700 → ไม่หัก
> ใบ 50 ทวิ ออกตามรูปแบบที่ snapshot ไว้กับรอบ (ต่อผู้รับต่อรอบ = ค่าเริ่มต้น / ต่อรายการ — `33`) และสรุป ภ.ง.ด. = ผลรวมของรายการ ⇒ ตรงกับยอดรวมของ payee โดยอัตโนมัติทั้งสองแบบ
> pure module: `lib/finance/wht-calc.ts` (`calculatePayeeBatchWht()`) · 🔶 นักบัญชียืนยันก่อน go-live

#### 6.9.2 เงื่อนไขการหัก (2) ออกให้ตลอดไป / (3) ออกให้ครั้งเดียว (มติ PO 06/10/2569 U105)

```
ปิด:  ผู้รับเลือกได้เฉพาะ (1) (ค่าเดิม (2)/(3) ที่ตั้งไว้ก่อนปิดคงไว้ได้)
      สร้างรอบจ่ายที่มีผู้รับ (2)/(3) และมีรายการในฐาน ⇒ ปัดทั้งรอบ WHT_CONDITION_NOT_ALLOWED (+ รายชื่อ)

เปิด: เกณฑ์ขั้นต่ำ (฿1,000) เทียบ SUM(ฐาน_i) = เงินได้ **ก่อนบวกภาษี** (เหมือน §6.9)
      ภาษีของกลุ่ม (ต่อผู้รับต่ออัตรา — ปัดครึ่งขึ้นเป็นสตางค์ครั้งเดียว แล้วกระจาย largest remainder เหมือน §6.9):
        (1) หัก ณ ที่จ่าย      wht = round(ฐาน × r)
        (2) ออกให้ตลอดไป      wht = round(ฐาน × r ÷ (1 − r))       (r = อัตรา/100 · คิดจำนวนเต็มด้วย basis point)

      ⇒ net = gross − wht ยังจริงทุกแถว (§6.10 ไม่เปลี่ยน) · ยอดโอน = net − หักคืนเงินทดรอง (§6.14)
      เงินได้บนใบ 50 ทวิ / 05_WHT_Data / สรุป ภ.ง.ด. = SUM(gross ในฐาน) = เงินได้ + ภาษีที่ออกให้
      เอกสาร: ใบสำคัญจ่าย/สลิป แสดงค่าตอบแทน = net · บรรทัดแยก "ภาษีที่บริษัทออกให้" = wht (ไม่หักจากยอดโอน)
              04_Payments/05_WHT_Data ต่อท้ายคอลัมน์ `wht_paid_by_payer_baht`
      รายการนอกฐาน/เงินทดรองจ่าย: ไม่บวกภาษี (gross = net = ยอดรายการ)

#### 6.11.1 ตัดส่วนต่างรับชำระขาดเป็นค่าธรรมเนียมธนาคาร (อ้างอิงไฟล์ 19 §9.2, 13 §6.2.1, 35) — มติ PO 07/10/2569 (U144 · B4)

```
shortfall          = total_amount − received_amount − wht_withheld_by_customer        (ยอดสะสม ณ ตอนรับเงิน)
bank_fee_write_off = shortfall   ถ้า received_amount > 0 และ 0 < shortfall ≤ write_off_tolerance_satang
                   = 0           กรณีอื่น (ยังไม่รับเงินเลย · รับครบ/เกิน · ขาดเกินเพดาน · เพดาน = 0)
สถานะรอบ           = paid เมื่อ settled ≥ total_amount (settled รวม bank_fee_write_off — §6.11)
วันที่ตัด           = วันรับเงินล่าสุดของรอบ (date-only) · ยอดตัดเท่าเดิม = วันที่เดิม
```

- **คำนวณใหม่จากยอดสะสมทุกครั้ง** (idempotent — ไม่สะสมทับ): รับเงินเพิ่มจนครบภายหลัง ⇒ ยอดตัดกลับเป็น 0 · ถอนการจับคู่จนยอดรับลด ⇒ ประเมินใหม่
- เพดาน = `finance_policy_settings.write_off_tolerance_satang` (ค่าเริ่มต้น 5,000 สตางค์ = ฿50) ณ ตอนรับเงิน — snapshot ลง audit · ไม่ย้อนแก้เมื่อเปลี่ยนค่าตั้ง
- เท่าเพดานพอดีตัดได้ · เกิน 1 สตางค์ไม่ตัด · Implementation: `lib/finance/ar-calc.ts` (`resolveBankFeeWriteOff` · `settledSatang`)

**ภาษีลูกค้าหัก + ค่าธรรมเนียมโอนในรายการเดียว (มติ PO 07/10/2569 U163 · ต่อยอด A1)** — ตัดสินตอนสร้างใบเงินรับ (จับคู่เงินเข้า) **ก่อน** คำนวณค่าธรรมเนียมข้างบน:

```
expected_wht  = total_amount − ยอดคาดรับ (§6.16)          · บริษัทไม่ได้ตั้งให้หัก ⇒ 0 ⇒ ข้ามกติกานี้ (พฤติกรรม U144 เดิม)
net           = total_amount − expected_wht
cumulative    = ยอดรับของใบเงินรับใบก่อน ๆ ของรอบ + ยอดเงินเข้าของใบนี้
wht ของใบนี้   = max(0, expected_wht − wht ที่ใบก่อน ๆ บันทึกแล้ว)   ถ้า net − write_off_tolerance ≤ cumulative ≤ net
              = 0                                                  กรณีอื่น (รับเต็มยอดบิล · ขาดเกินช่วง · ยอดอยู่ระหว่าง net กับ total)
```

- **นับภาษีก่อน ส่วนต่างที่เหลือเป็นค่าธรรมเนียม** — หลังบันทึกภาษีแล้ว `shortfall` ข้างบน = `net − cumulative` (≤ เพดาน) ⇒ ค่าธรรมเนียมธนาคาร · รอบ `paid`
- เพดาน = 0 ⇒ เหลือเฉพาะเงินเข้า = `net` พอดี (= กติกา A1 เดิม) · ภาษีที่บันทึกเกิดรายการ "รอ 50 ทวิ จากลูกค้า" (U40) เท่ายอดภาษีเต็ม
- ล็อกแถวรอบวางบิลระหว่างตัดสิน (กันสองรายการเดินบัญชีนับภาษีซ้ำ) · Implementation: `resolveCustomerWhtForReceipt` (`lib/finance/ar-calc.ts`) ผ่าน `whtWithheldForReceipt` (`lib/bank-recon/matching.ts`)
- ⚠️ สมมติฐานรอนักบัญชียืนยัน (ป้ายที่ค่าตั้งเพดาน) · งวดที่ล็อกแล้วแก้ผ่าน Adjustment ตามกติกาเดิม

### 6.14 เงินทดรองจ่าย — ยอดคืนค้าง + หักกลบในรอบจ่าย (อ้างอิงไฟล์ 15 §9.3, 17 §6.4) — มติ PO 05/10/2569 (UAT U30)

```
return_outstanding = return_amount - SUM(advance_returns.amount WHERE reversed_at IS NULL)
                     (ห้ามติดลบ — ได้คืนเกิน return_amount = ข้อมูลเพี้ยน ต้อง error)

ตอนสร้างรอบจ่าย ต่อผู้รับ 1 คน (เฉพาะเงินทดรองที่ return_method = payout_offset):
  lines   = net_amount ของแต่ละบรรทัดของผู้รับในรอบ (หลัง WHT แล้ว — §6.9) ตามลำดับในรอบ
  returns = return_outstanding ของแต่ละเงินทดรอง เรียงเคลียร์ก่อน-หลัง (FIFO)
  หักทีละเงินทดรอง × ทีละบรรทัด: take = min(คงเหลือของบรรทัด, คงเหลือของเงินทดรอง)
  item.advance_offset_amount = ยอดที่หักจากบรรทัดนั้น (0 ≤ ค่านี้ ≤ item.net_amount)
  item.transfer_amount       = item.net_amount - item.advance_offset_amount   (ไม่ติดลบ)
  ส่วนที่หักไม่หมด = ยกไปรอบถัดไป (ยังเป็น return_outstanding)

gross / wht / net ของรายการและของรอบ **ไม่เปลี่ยน** ⇒ ฐาน WHT และ 50 ทวิ ไม่กระทบ
```

> ตัวอย่าง: ค้าง ฿550 · รอบได้สุทธิ ฿4,850 (gross ฿5,000 WHT ฿150) → หัก ฿550 โอน ฿4,300 · รอบได้สุทธิ ฿300 → หัก ฿300 โอน ฿0 ยก ฿250

### 6.17 ใบรับรองแทนใบเสร็จรับเงิน — ยอดรวม + เพดาน (อ้างอิงไฟล์ 15 §9.4, 41 §6.6, 13 §6.2.1) — มติ PO 06/10/2569 (U103)

```
ยอดรวมของใบ (สตางค์)   = Σ amount_satang ของทุกบรรทัด   (แต่ละบรรทัด > 0 · ≥ 1 บรรทัด · ≤ 15 บรรทัด) — snapshot ที่ substitute_receipts.total_satang
ยอดของเดือน          = Σ total_satang ของใบที่ออกแล้วของผู้จ่ายคนเดียวกัน ที่ issue_date อยู่เดือนเดียวกัน (วันไทย)
                       ไม่นับ: ใบที่ถูกลบ · ใบของใบเบิกที่ rejected/superseded/ถูกลบ
ตรวจ (ตามลำดับ)       : ยอดรวมของใบ > เพดานต่อใบ                       → บล็อก SUBSTITUTE_RECEIPT_EXCEEDS_LIMIT
                       ยอดของเดือน + ยอดรวมของใบ > เพดานต่อเดือน         → บล็อก SUBSTITUTE_RECEIPT_EXCEEDS_LIMIT
                       ยอดที่ยังออกได้ = max(0, เพดานต่อเดือน − ยอดของเดือน)  (แสดงในข้อความ)
เพดาน                 = finance_policy_settings.substitute_receipt_max_per_doc_satang (ค่าเริ่มต้น 50,000)
                       / …_max_per_month_satang (ค่าเริ่มต้น 300,000)
```

- **บล็อก ไม่ตัดยอด** — เท่าเพดานพอดีผ่าน เกิน 1 สตางค์บล็อก · ตรวจในทรานแซกชันเดียวกับการออกเลข CRT หลังล็อกแถว `payee_profiles` (คำขอพร้อมกันของผู้จ่ายคนเดียวไม่ทะลุเพดานต่อเดือน)
- **ใบเบิกค่าที่พัก**: ยอดเบิก = ยอดรวมของใบเท่านั้น (ตรวจด้วย Zod ชุดเดียว FE/BE) แล้วยังต้องผ่านเพดานค่าที่พักต่อคืน §6.15 ตามเดิม
- **เคลียร์เงินทดรอง**: ยอดรวมของใบ ≤ ยอดใช้จริง (`used_satang`) — ส่วนที่เหลือมีใบเสร็จจริง · สูตรยอดคืน §6.13 ไม่เปลี่ยน
- **ฐาน WHT ไม่เปลี่ยน**: รายการเบิกที่ใช้ใบรับรองแทนใบเสร็จคงชนิดรายการเดิม (`hotel` ฯลฯ) ⇒ ตัวจำแนกฐานตามค่าตั้ง U3 (§6.9) จัดเป็น "ค่าใช้จ่ายตามใบเสร็จ" เหมือนรายการที่มีใบเสร็จทุกประการ (ค่าเริ่มต้นไม่อยู่ในฐาน) · ใบที่ผูกเงินทดรองไม่เข้ารอบจ่ายจึงไม่เกี่ยวกับ WHT
- Implementation: `lib/substitute-receipts/substitute-receipt.ts` (`substituteReceiptTotalSatang` / `substituteReceiptLimitProblem` / `assertWithinSubstituteReceiptLimits` / `substituteReceiptMonthRange`)

## 17. การตัดสินใจที่เกี่ยวข้อง (Decisions)

- **Allowance คำนวณต่อวันที่ลงพื้นที่จริง** ไม่ใช่ค่าคงที่ต่อเคส — แก้ไขแล้วให้ตรงกับหน่วย "บาท/วัน" ในไฟล์ 11 (§6.3)
- **ค่าน้ำมันเหมาจ่าย + เบี้ยเลี้ยง = วันละครั้งต่อพนักงาน แล้วเฉลี่ยทุกเคสของวันนั้น · เกิดหลังจบวัน** — มติ PO 03/10/2569 (UAT Q21 · DEC-012) (§6.2/§6.3)
- **Revenue เกิดที่จุด `expense.approved`** ไม่ใช่ตอน `closed_success` ตรงๆ — สอดคล้องกับ Warehouse gate ในไฟล์ 19 (§6.5)
- **WHT Rate Priority: Payee level ชนะ Plan level เสมอ** — Payee level = Tax Profile รายคน → ค่าเริ่มต้นตามประเภทผู้รับ (มติ PO U121) · fallback ไป Plan level เฉพาะเมื่อไม่มีทั้งสองข้อ · ไม่มีอัตราเลย = บล็อกรอบจ่าย (§6.9)
- **VAT snapshot ที่ Revenue Record เสมอ** ไม่ดึงอัตราสดทุกครั้งที่แสดงผล (§6.8)
- **Commission/No-Success Fee เป็น mutually exclusive ตาม outcome** ไม่มีการหารเฉลี่ยเคสต่อวัน "กฎหาร 4" ถูกยกเลิกแล้ว (§6.4)
- **Margin % ต้องไม่หารด้วย 0** — แสดง "N/A" เมื่อ revenue = 0 (§6.12)
