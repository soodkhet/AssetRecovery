## 1. Summary

รวมรายการเอกสาร PDF ทั้งหมดที่ระบบต้องสร้างได้ แบ่งเป็น **เอกสารภายใน** (ไม่มีผลทางกฎหมาย) และ **เอกสารทางการ** (มีข้อกำหนดทางกฎหมายต้องมีฟิลด์ครบ)

## 2. Purpose

เป็น checklist ครบถ้วนของเอกสารที่ต้อง implement พร้อมระบุว่าฟิลด์ไหนบังคับตามกฎหมาย

## 3-5. (ไม่ใช้กับไฟล์ประเภทนี้)

เอกสารนี้เป็น technical reference ล้วน — ไม่มี Scope/Actor ของตัวเอง

## 6. รายการเอกสาร PDF ทั้งหมด

### 6.1 เอกสารภายใน (Internal — ไม่มีข้อกำหนดทางกฎหมาย, อ้างอิงไฟล์ 13 §6.7)

| เอกสาร | ใช้เมื่อ | ข้อมูลหลัก |
|---|---|---|
| Internal Billing Summary | ก่อนออกเอกสารทางการ | สรุปยอดวางบิลภายใน |
| Payout Batch Summary | ก่อนโอนเงินจริง | สรุปรอบจ่ายเงิน |
| Payment Voucher ภายใน | หลังจ่ายเงินสำเร็จ | หลักฐานภายใน |
| Compensation Statement / Payslip | สรุปค่าตอบแทนต่อพนักงาน/รอบ | รายละเอียดค่าตอบแทนจากเคส |
| Accounting Pack Cover Sheet | ส่งสำนักงานบัญชีรายเดือน | หน้าปกชุดเอกสาร |

### 6.2 เอกสารทางการ — ใบกำกับภาษี (ไฟล์ 31 §6.2) 🔶 มีข้อกำหนดทางกฎหมายเข้มงวด

**ฟิลด์บังคับตามกฎหมาย** (ใบกำกับภาษีแบบเต็มรูป):

- คำว่า "ใบกำกับภาษี" ในที่เห็นเด่นชัด
- ชื่อ/ที่อยู่/เลขประจำตัวผู้เสียภาษีของผู้ออก (AssetRecovery)
- ชื่อ/ที่อยู่/เลขประจำตัวผู้เสียภาษีของผู้ซื้อ (บริษัทไฟแนนซ์)
- เลขที่ใบกำกับภาษี (running ต่อเนื่อง — ตามไฟล์ 13 §6.12)
- วันเดือนปีที่ออก
- รายการ/ปริมาณ/มูลค่าสินค้าหรือบริการ
- จำนวนภาษีมูลค่าเพิ่มที่คำนวณจากมูลค่าสินค้าหรือบริการ แยกออกจากมูลค่าสินค้า/บริการอย่างชัดแจ้ง

รองรับทั้ง 2 รูปแบบ (ตามที่ Product Owner ยืนยันแล้ว):

- **e-Tax Invoice**: format ตามที่กรมสรรพากรกำหนดสำหรับนำส่งระบบ e-Tax
- **Paper/PDF**: เอกสารพิมพ์ส่งทางไปรษณีย์/อีเมล

### 6.3 เอกสารทางการ — หนังสือรับรองการหักภาษี ณ ที่จ่าย (ใบ 50 ทวิ) (ไฟล์ 33 §6.3) 🔶 มีข้อกำหนดทางกฎหมายเข้มงวด

**ฟิลด์บังคับตามกฎหมาย**:

- เลขประจำตัวผู้เสียภาษี/ชื่อ-ที่อยู่ของผู้จ่ายเงิน (AssetRecovery)
- เลขประจำตัวผู้เสียภาษี (หรือเลขบัตรประชาชน)/ชื่อ-ที่อยู่ของผู้ถูกหักภาษี (Payee)
- ลำดับที่ของหนังสือรับรอง
- ประเภทเงินได้พึงประเมินที่จ่าย (ระบุมาตรา เช่น "ค่าจ้างทำของ มาตรา 40(8)")
- จำนวนเงินที่จ่ายและจำนวนภาษีที่หักไว้ในแต่ละครั้งที่มีการหักภาษี
- วันเดือนปีที่จ่ายเงิน

รองรับทั้ง 2 รูปแบบเช่นกัน: e-Withholding Tax และกระดาษ

### 6.4 Document Checklist Export (ไฟล์ 34, ใช้ XLSX ไม่ใช่ PDF)

ไม่ใช่ PDF — เป็น `.xlsx` ตามที่ไฟล์ 13 §6.9/ไฟล์ 37 §6.1 ระบุไว้ — สรุปสถานะ Exception แต่ละรายการ

## 7. Implementation Notes

- **สำหรับการ Generate PDF ฝั่ง Server ให้ใช้ Library `@react-pdf/renderer`** เพื่อดึงข้อมูลจาก Database (ผ่าน Prisma) มาสร้างเป็นไฟล์ PDF ให้ผู้ใช้ดาวน์โหลด — เลือกใช้เพราะเขียนเป็น React component (JSX) ได้ ควบคุม layout เอกสารทางการที่ซับซ้อนตาม §6.2/§6.3 ได้ตรงจุด และเข้ากับ Tech Stack Next.js/TypeScript ที่ตัดสินใจไว้แล้ว (DEC-001)
  - รูปแบบการใช้งานคร่าวๆ: สร้าง React component แยกตามประเภทเอกสาร (เช่น `TaxInvoicePDF.tsx`, `WhtCertificatePDF.tsx`) → เรียก `renderToStream()`/`renderToBuffer()` จาก `@react-pdf/renderer` ใน API Route → คืนไฟล์ PDF พร้อม header `Content-Type: application/pdf`
  - ทางเลือกสำรอง (ถ้าเจอข้อจำกัดด้าน layout ที่ `@react-pdf/renderer` ทำไม่ได้): `pdfmake` — แต่ให้เริ่มจาก `@react-pdf/renderer` เป็นหลักก่อนเสมอ
- เอกสารทางการ (§6.2, §6.3) ต้องมี layout ตรงตามแบบฟอร์มมาตรฐานที่กรมสรรพากรยอมรับ — แนะนำให้นักบัญชี/สำนักงานบัญชีตรวจสอบ template จริงก่อนใช้งาน production
- ทุกเอกสารทางการต้องมี watermark/QR code หรือ digital signature ตามที่กฎหมาย e-Tax/e-WHT กำหนด หากเลือกออกแบบอิเล็กทรอนิกส์ 🔶 รายละเอียดเทคนิคของ digital signature ต้องศึกษาเพิ่มเติมตอน implement จริง ไม่ครอบคลุมในสเปคนี้

## 17. การตัดสินใจที่เกี่ยวข้อง (Decisions)

- **เอกสารทางการรองรับ 2 รูปแบบเสมอ**: e-Tax/e-Withholding และ Paper/PDF — ยืนยันจาก Product Owner แล้ว (§6.2, §6.3)
- **ฟิลด์บังคับตามกฎหมายปิด/ซ่อนไม่ได้** — ปรับได้แค่ layout/โลโก้/footer ผ่านไฟล์ 13 §6.13 (§7)
- **Document Checklist Export เป็น XLSX ไม่ใช่ PDF** — ต่างจากเอกสารอื่นในไฟล์นี้ (§6.4)

## 18. สิ่งที่ยังต้องตัดสินใจ (Open Items)

- Layout/ภาพลักษณ์ของใบกำกับภาษีและใบ 50 ทวิ ทำเป็นค่าตั้งค่าได้แล้ว (ดูไฟล์ 13 §6.13) ให้สำนักงานบัญชีปรับโลโก้/footer/ขนาดกระดาษ/ภาษาเองได้ — ฟิลด์บังคับตามกฎหมายยังคงครบตามที่ระบุใน §6.2-6.3 เสมอ ไม่สามารถปิดได้
- รายละเอียดทางเทคนิคของการเชื่อมต่อระบบ e-Tax Invoice/e-Withholding Tax ของกรมสรรพากรยังไม่ได้ศึกษา (ดู Open Items ของไฟล์ 31, 33 ด้วย)
