## 6. รายการเอกสาร PDF ทั้งหมด

### 6.0 หัวเอกสารกลาง (Letterhead) — มติ PO 06/10/2569 (U99)

- **component ชุดเดียว** ใน `components/pdf/doc-layout.tsx` (มติ PO U100 — แทน `<Letterhead>` เดิม): `<DocTitleHeader>` (เอกสารที่มีชื่อเอกสาร + ฉบับ) และ `<InternalHeader>` (แถบหัวเอกสารภายใน) · ข้อมูลองค์กรเต็มชุด (ที่อยู่ / "โทร. · อีเมล · เว็บไซต์" / "เลขประจำตัวผู้เสียภาษี … · สำนักงานใหญ่|สาขาที่ …") พิมพ์ใน**กล่องฝ่ายเรา** (`letterheadPartyLines()`) ของเอกสารที่มีกล่องสองฝ่าย
- หัวเอกสาร: โลโก้ (ถ้ามี) ซ้าย + ชื่อไทย / ชื่ออังกฤษ · ไม่มีโลโก้ = ไม่เว้นกล่องว่าง · ช่องที่ไม่มีค่า = ไม่พิมพ์บรรทัด
- แหล่งข้อมูล: **ใบกำกับภาษี/ใบเสร็จรับเงิน + ใบแจ้งหนี้** = snapshot บนเอกสาร (ชื่อ/เลข/ที่อยู่/โทร/สาขา + `seller_profile_snapshot`) — เอกสารก่อน U99 ไม่มีชุดเพิ่ม ⇒ ใช้ค่าปัจจุบัน**เฉพาะ** ชื่ออังกฤษ/อีเมล/เว็บไซต์/โลโก้ · **เอกสารภายใน** (ใบสำคัญจ่าย/สลิป/สรุปรอบ/ใบส่งมอบ/รายงาน/หน้าปก) = ค่าปัจจุบันขององค์กร
- ใบกำกับภาษี/ใบแจ้งหนี้: ผู้ขายพิมพ์ในกล่อง "ชำระให้/ผู้เรียกเก็บ" จากหัวเอกสารที่ประกอบจาก snapshot บนเอกสาร (ฟิลด์บังคับตาม ม.86/4 ครบ) · ผู้ซื้อในกล่อง "ชำระโดย/เรียกเก็บจาก" จาก snapshot
- **แบบ 50 ทวิ (§6.3) ไม่ใช้หัวเอกสารกลาง** — คงแบบฟอร์มทางการ ช่อง "ผู้มีหน้าที่หักภาษี" พิมพ์จาก snapshot ผู้หักบนใบ (ไม่มีที่สำหรับโลโก้ในแบบ)
- โลโก้: `downloadUploadedFile()` (service role) → ตรวจ PNG/JPG จาก magic bytes → ฝังเป็นรูป · โหลดไม่ได้ = พิมพ์โดยไม่มีโลโก้ (ไม่ทำให้การออกเอกสารล้ม) · Export Pack cache โลโก้ต่อ path ต่อชุด

### 6.0.1 เลย์เอาต์เอกสารตามแบบที่อนุมัติ — มติ PO 06/10/2569 (U100/U101)

ต้นแบบหน้าตา = `reference/documents.html` (ผู้ใช้อนุมัติแล้ว) · ชิ้นส่วนร่วม `components/pdf/doc-layout.tsx`

- **หัว**: โลโก้ + ชื่อบริษัทซ้ายบน · ชื่อเอกสารตัวใหญ่สีน้ำเงินเข้ม + ชื่ออังกฤษ + ป้ายฉบับ "(ต้นฉบับ / Original)" / "(สำเนา / Copy)" ขวาบน
- แถว "วันที่: …" (ซ้าย, พ.ศ.) / "เลขที่: …" (ขวา, ตัวอักษรความกว้างคงที่) + ข้อมูลประกอบ 2 คอลัมน์
- **กล่องสองฝ่าย** (ขอบเส้น) — ชื่อ · โทร · ที่อยู่ · เลขประจำตัวผู้เสียภาษี + สาขา
- **ตาราง** ขอบเส้น หัวตารางพื้นเทา (พิมพ์ซ้ำทุกหน้าเมื่อรายการยาว) · แถวหัก = สีแดง ยอดในวงเล็บ · แถวรวม = พื้นเทา · "ช่องทางการชำระเงิน : …" · "จำนวนเงิน: -…บาทถ้วน-" (`bahtInWords()`)
- ช่องลายเซ็น (เส้นประ · ( …… ) · บทบาท · วันที่) · ท้ายกระดาษ "ชื่อบริษัท · เลขที่เอกสาร" / "หน้า x/y" (**นับต่อฉบับ**)
- ข้อมูลทั่วไปพอดี A4 หน้าเดียวต่อฉบับ · รายการยาวขึ้นหน้าใหม่ (แถวไม่ถูกตัดกลาง)
- ฟอนต์: Noto Sans Thai 2 น้ำหนัก — ปกติ + **ตัวหนา** (v2.6 · BUG-171) · เลขอ้างอิง/IMEI ที่เป็นอักษรละตินล้วนใช้ Courier

### 6.2 เอกสารทางการ — ใบกำกับภาษี (ไฟล์ 31 §6.2) 🔶 มีข้อกำหนดทางกฎหมายเข้มงวด

**ฟิลด์บังคับตามกฎหมาย** (ใบกำกับภาษีแบบเต็มรูป):

- คำว่า "ใบกำกับภาษี" ในที่เห็นเด่นชัด
- ชื่อ/ที่อยู่/เลขประจำตัวผู้เสียภาษีของผู้ออก (AssetRecovery)
- ชื่อ/ที่อยู่/เลขประจำตัวผู้เสียภาษีของผู้ซื้อ (บริษัทไฟแนนซ์)
- เลขที่ใบกำกับภาษี (running ต่อเนื่อง — ตามไฟล์ 13 §6.12)
- วันเดือนปีที่ออก
- รายการ/ปริมาณ/มูลค่าสินค้าหรือบริการ
- จำนวนภาษีมูลค่าเพิ่มที่คำนวณจากมูลค่าสินค้าหรือบริการ แยกออกจากมูลค่าสินค้า/บริการอย่างชัดแจ้ง

รองรับทั้ง 2 รูปแบบ (ตามที่ Product Owner ยืนยันแล้ว):

- **e-Tax Invoice**: format ตามที่กรมสรรพากรกำหนดสำหรับนำส่งระบบ e-Tax
- **Paper/PDF**: เอกสารพิมพ์ส่งทางไปรษณีย์/อีเมล

### 6.3 เอกสารทางการ — หนังสือรับรองการหักภาษี ณ ที่จ่าย (ใบ 50 ทวิ) (ไฟล์ 33 §6.3) 🔶 มีข้อกำหนดทางกฎหมายเข้มงวด

**ฟิลด์บังคับตามกฎหมาย**:

- เลขประจำตัวผู้เสียภาษี/ชื่อ-ที่อยู่ของผู้จ่ายเงิน (AssetRecovery)
- เลขประจำตัวผู้เสียภาษี (หรือเลขบัตรประชาชน)/ชื่อ-ที่อยู่ของผู้ถูกหักภาษี (Payee)
- ลำดับที่ของหนังสือรับรอง
- ประเภทเงินได้พึงประเมินที่จ่าย (ระบุมาตรา เช่น "ค่าจ้างทำของ มาตรา 40(8)")
- จำนวนเงินที่จ่ายและจำนวนภาษีที่หักไว้ในแต่ละครั้งที่มีการหักภาษี
- วันเดือนปีที่จ่ายเงิน

รองรับทั้ง 2 รูปแบบเช่นกัน: e-Withholding Tax และกระดาษ

**แบบฟอร์ม (มติ PO 06/10/2569 — UAT U96 #13)**: เลย์เอาต์ตามแบบหนังสือรับรองของกรมสรรพากร — ฉบับที่ 1 (แนบพร้อมแบบแสดงรายการ) + ฉบับที่ 2 (เก็บเป็นหลักฐาน) เป็น 2 หน้าใน PDF เดียว · ผู้มีหน้าที่หัก/ผู้ถูกหัก (ชื่อพร้อมคำนำหน้า · เลข 13 หลัก · สาขา · ที่อยู่ — จาก snapshot ของใบ) · ลำดับที่ในแบบ + ช่องแบบ ภ.ง.ด.1ก/1ก พิเศษ/2/3/2ก/3ก/53 · ตารางประเภทเงินได้ 6 แถวตามแบบ (ยอดลงแถวที่ตรงประเภท) · รวม + จำนวนภาษีเป็นตัวอักษร · ช่องเงินสมทบ กบข./ประกันสังคม/กองทุนสำรองเลี้ยงชีพ (ว่างให้กรอก) · ผู้จ่ายเงิน (1)–(4) · คำเตือน · ลงชื่อผู้จ่ายเงิน + วันที่ออก พ.ศ. — รายละเอียดที่ไฟล์ 33 §6.3 · ห้ามพิมพ์เลขอ้างอิงสเปคบนเอกสาร

### 6.5 หน้าตัวอย่างเอกสารทั้งหมด — มติ PO 06/10/2569 (U104)

ให้นักบัญชี/ผู้เกี่ยวข้องดูหน้าตาเอกสารทุกชนิดที่ระบบออกได้ในที่เดียว — เมนู **บัญชี → ตัวอย่างเอกสารทั้งหมด** (`/accounting/document-samples` · `06` §7.2 v2.11)

- **รายการ** (13 ตัวอย่าง แบ่ง 4 กลุ่ม): ใบแจ้งหนี้/ใบวางบิล · ใบเสร็จรับเงิน/ใบกำกับภาษี (+ ฉบับออกแทน · รับชำระบางส่วน) · ใบส่งมอบทรัพย์ · ใบสำคัญจ่าย · สลิปค่าตอบแทน · 50 ทวิ · ใบเบิกเงินทดรอง · ใบรับคืนเงินทดรอง · ใบรับรองแทนใบเสร็จรับเงิน · สรุปรอบจ่ายเงิน · หน้าปกชุดเอกสารบัญชี — การ์ดละ 1 ชนิด: ใครได้รับ / ออกเมื่อ / จำนวนฉบับ / ผู้เซ็น (ตาม §6.0.1 + §6.1) / เลขตัวอย่าง + รูปแบบเลข · ปุ่ม "ดูตัวอย่าง" (viewer ในหน้า) + "ดาวน์โหลด PDF"
- **เนื้อหา PDF**: component + builder **ตัวเดียวกับเอกสารจริง** (แก้แบบเอกสาร = ตัวอย่างเปลี่ยนตามเอง) · ข้อมูลธุรกรรม = **ข้อมูลสมมติคงที่** (`lib/documents/samples/fixtures.ts` — คู่ค้า/ผู้รับเงิน/ลูกหนี้/เลขเคสเป็นชื่อสมมติทั้งหมด **ห้ามดึงข้อมูลจริงจากฐาน**) · ผู้ออกเอกสาร = **หัวเอกสาร/โลโก้ขององค์กรปัจจุบัน** (§6.0) · วันที่ = วันที่เปิดดู
- **ป้ายตัวอย่าง**: ทุกหน้าพิมพ์ลายน้ำ "ตัวอย่าง" ทแยงกลางหน้า + แถบบนสุด "ตัวอย่าง — ไม่ใช่เอกสารจริง" (`components/pdf/sample-stamp.tsx` — เปิดด้วย `<SampleMode>` ห่อเอกสาร · เอกสารจริงไม่ห่อจึงไม่มีป้าย) · ชื่อไฟล์ดาวน์โหลดขึ้นต้น "ตัวอย่าง-"
- **เลขที่เอกสาร**: แสดง "เลขถัดไป" ตามค่าตั้ง `document_number_series` ปัจจุบัน (`13` §6.12 — ตัวเดียวกับตัวอย่างเลขบนหน้าตั้งค่า) · **อ่านอย่างเดียว ไม่เดินตัวนับ ไม่สร้างแถวชุดเลข** · สรุปรอบจ่าย/หน้าปกไม่มีเลขจากชุดเลข
- **สิทธิ์**: `view_document_samples` (บัญชี/การเงิน/บริหาร ระดับ view · Superadmin โดยนิยาม — `25` §7.1) · endpoint `GET /api/accounting/document-samples` + `GET /api/accounting/document-samples/:docType/pdf` (`27` §6.12)
- **Audit**: ไม่ลง audit `export` — ไม่มีข้อมูลจริงของลูกค้า/ผู้รับเงินออกจากระบบ และเป็น GET อ่านอย่างเดียว (ไม่ใช่ mutation)

## 7. Implementation Notes

- **สำหรับการ Generate PDF ฝั่ง Server ให้ใช้ Library `@react-pdf/renderer`** เพื่อดึงข้อมูลจาก Database (ผ่าน Prisma) มาสร้างเป็นไฟล์ PDF ให้ผู้ใช้ดาวน์โหลด — เลือกใช้เพราะเขียนเป็น React component (JSX) ได้ ควบคุม layout เอกสารทางการที่ซับซ้อนตาม §6.2/§6.3 ได้ตรงจุด และเข้ากับ Tech Stack Next.js/TypeScript ที่ตัดสินใจไว้แล้ว (DEC-001)
  - รูปแบบการใช้งานคร่าวๆ: สร้าง React component แยกตามประเภทเอกสาร (เช่น `TaxInvoicePDF.tsx`, `WhtCertificatePDF.tsx`) → เรียก `renderToStream()`/`renderToBuffer()` จาก `@react-pdf/renderer` ใน API Route → คืนไฟล์ PDF พร้อม header `Content-Type: application/pdf`
  - ทางเลือกสำรอง (ถ้าเจอข้อจำกัดด้าน layout ที่ `@react-pdf/renderer` ทำไม่ได้): `pdfmake` — แต่ให้เริ่มจาก `@react-pdf/renderer` เป็นหลักก่อนเสมอ
- เอกสารทางการ (§6.2, §6.3) ต้องมี layout ตรงตามแบบฟอร์มมาตรฐานที่กรมสรรพากรยอมรับ — แนะนำให้นักบัญชี/สำนักงานบัญชีตรวจสอบ template จริงก่อนใช้งาน production
- ทุกเอกสารทางการต้องมี watermark/QR code หรือ digital signature ตามที่กฎหมาย e-Tax/e-WHT กำหนด หากเลือกออกแบบอิเล็กทรอนิกส์ 🔶 รายละเอียดเทคนิคของ digital signature ต้องศึกษาเพิ่มเติมตอน implement จริง ไม่ครอบคลุมในสเปคนี้
